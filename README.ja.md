# MMDEncoder

[English](README.en.md) | [简体中文](README.md) | **日本語**

MMD クリエイター向けの Windows 用ポータブル動画エンコードツールです。レンダリング動画の一括エンコード、アルファチャンネルの処理、AI / RTX による高解像度化とフレーム補間、無劣化カットに対応し、MMD の動画エンコーダーとして完成動画を直接書き出すこともできます。

プロジェクト：<https://github.com/CicloO/MMDEncoder>

## 機能

- **一括エンコード**：H.264 / HEVC / AV1 / VP9 / ProRes、MP4 / MKV / MOV / WebM。ソフトウェアエンコード、NVENC、NVEncC、Intel QSV、AMD AMF。
- **プリセット**：アップロード用（標準 4K / 1080p、ハードウェアとソフトウェアを各 1 つ）と編集素材用（ProRes 4444、H.264＋マスク、ProRes 422 HQ）を内蔵。個人プリセットは保存、インポート／エクスポート、ドラッグでの並べ替えが可能です。
- **アルファチャンネル**：アルファを保持、白黒マスクに分離、マスクのみ書き出し、グリーンバックに合成。
- **高画質化**：ArtCNN AI 拡大（Vulkan 対応の GPU なら可）、RTX VSR 超解像、RTX フレーム生成。
- **無劣化カット**：区間を切り出して前後につなげます。映像は再エンコードしません。フレーム番号、時間、MMD のフレーム番号で位置を指定できます。
- **MMD 出力プラグイン**：MMD の「AVI 出力」で「MMDEncoder」を選ぶと、プリセットどおりに音声付きの完成動画を直接書き出せます。巨大な AVI は作りません。
- **音声・映像ツール**：音声トラックの抽出、削除、差し替え。Hi-Res 音声も選べます。
- **PNG 連番**：連番の PNG を動画としてエンコード。透過にも対応します。
- **安全な出力**：元ファイルや既存の出力を上書きしません。ハードウェアエンコードが失敗したらソフトウェアで再試行でき、実際に実行したコマンドもコピーできます。
- **画面**：日本語 / 简体中文 / English。Windows の表示言語に合わせることもできます。昼 / 夜テーマ、テーマカラーはネオンシアンまたはコバルトブルー。

## 動作環境

|            | 最低限の目安                       | 推奨                                                    |
| ---------- | ---------------------------------- | ------------------------------------------------------- |
| OS         | Windows 10 / 11（64 ビット）       | Windows 11（64 ビット）                                 |
| CPU        | 4 コアの x64                       | 6 コア以上（4K の場合）                                 |
| メモリ     | 8 GB                               | 16 GB 以上（4K や AI 拡大は 16～32 GB）                 |
| GPU        | 基本機能には不要                   | ハードウェアエンコーダー搭載の NVIDIA / AMD / Intel GPU |
| ストレージ | ソフト、ツール、出力ファイルの容量 | SSD。複雑な処理では出力予定サイズの 2～3 倍を確保       |

- ソフトウェアエンコード、ProRes、無劣化カット、音声・映像ツールは CPU だけで動作します。
- ハードウェアエンコードには対応する NVIDIA（NVENC）、Intel（QSV）、AMD（AMF）の GPU とドライバーが、ArtCNN 拡大には Vulkan 対応 GPU が必要です。
- RTX VSR には NVIDIA RTX GPU が、RTX VFG フレーム生成には RTX 40 / 50 シリーズと NVEncC 9.36 以降が必要です。どちらも NVEncC でエンコードします。
- エンコードツールの初回インストールにはインターネット接続が必要です。その後のローカルエンコードはオフラインで行えます。
- 各機能が使えるかどうかは、ソフト内の検出とテストエンコードの結果で判断してください。

機能ごとの要件、作業別の目安、ストレージについては [システムとハードウェアの要件](docs/系统与硬件要求.md)（中国語）をご覧ください。

## インストール

1. [Releases](https://github.com/CicloO/MMDEncoder/releases) から `MMDEncoder-<バージョン>-win-x64.zip` をダウンロードし、任意のフォルダーに展開して `MMDEncoder.exe` を実行します。
2. 初回は「エンコードエンジン」で「最新ツールをダウンロードしてインストール」をクリックします。手元の ZIP / 7z ツールパッケージを使う場合は「アーカイブからインストール」を選びます。インストール後はオフラインで使えます。

エンコードツール（[FFmpeg / ffprobe](https://www.gyan.dev/ffmpeg/builds/)、[NVEncC](https://github.com/rigaya/NVEnc/releases)）は同梱していません。既定では `%LOCALAPPDATA%\MMDEncoder\tools` にインストールされ、管理者権限は不要です。場所の変更や更新の確認は「エンコードエンジン」で行えます。ローカルの FFmpeg パッケージには `ffmpeg.exe` と `ffprobe.exe` の両方が、NVEncC パッケージには `NVEncC.exe` または `NVEncC64.exe` が必要です。

**ソフトウェア更新**：上部バーの「情報と言語」で行います。起動時に GitHub Releases を確認し、新しいバージョンがあれば「ダウンロードして更新」をクリックします。SHA-256 を検証してからプログラムファイルを置き換え、`data` フォルダー（設定、個人プリセット、ログ）はそのまま残します。失敗した場合は自動で元に戻ります。編集した内蔵プリセットが新バージョンで変わっている場合は、新バージョンで上書きするか個人プリセットとして保存するかを確認します。新バージョンを手動でダウンロードし、旧バージョンの `data` をコピーしても構いません。

## 使い方

### 動画エンコード

「音声」タブでフェードイン／アウトを オフ、0.5、1、2 秒から選べます。

動画を追加し（ドラッグ＆ドロップ可）、プリセットを選んで、下部の「予定の結果」を確認してからエンコードを始めます。既定の出力先は元動画と同じフォルダーの `Encoded` サブフォルダーで、同名の場合は自動で番号を付けます。

- キューはドラッグで並べ替えられます。完了またはキャンセルした項目は「再出力」できます。
- 設定に互換性がない場合、下部のバーにワンクリックの修正案が表示され、関係する設定だけを変更します。
- **PNG 連番**：連番を入れたフォルダーをドラッグするか、その中の PNG を 1 枚選びます。ファイル名の末尾は連番である必要があり（例：`dance_0001.png`）、欠けたフレームがあれば知らせます。連番のフレームレートは「現在の素材」で設定します（既定 30）。
- **編集向け**（「詳細」タブ）：毎秒 1 つキーフレームを入れ、後で無劣化カットしやすくします。ファイルは約 2%～5% 大きくなります。
- **Hi-Res 音声**（「音声」タブ、FLAC / PCM）：24-bit。48 kHz 未満の場合はサンプルレートを 2 倍にします。
- **音声の差し替え**：キューの動画の横にある ♪ をクリックするか、動画を選んで音声ファイルをドラッグします。もう一度ドラッグすると、選択中の項目の音声を差し替えます。出力は動画の長さに合わせます。♪ を右クリックすると差し替えを、波形ボタンを右クリックすると位置合わせを取り消します（キーボードでは Shift+F10）。既定で有効な自動位置合わせは「情報 → 設定」でオフにできます。既存のオフセットは保持され、手動での位置合わせも引き続き使えます。

### アルファチャンネル

「アルファ」タブで次の中から選べます。

- **アルファを削除**：透明部分を元のピクセルの色のまま出力します。
- **アルファを保持**：ProRes 4444、VP9（WebM / MKV）、NVEncC HEVC のみ。
- **アルファ分離**：カラー動画と、同名で `_alpha` の付いたロスレス白黒マスク。どの形式でも使えます。
- **白黒マスクのみ**：`_alpha` マスクだけを書き出します。
- **グリーンバックに合成**：透明部分を #00FF00 で塗りつぶします。

| 形式        | 透過を読み込める                                          | 透過を読み込めない                                       |
| ----------- | --------------------------------------------------------- | -------------------------------------------------------- |
| ProRes 4444 | After Effects、Premiere、DaVinci、Final Cut               | ほぼなし                                                 |
| VP9（WebM） | Chrome、Firefox、OBS ブラウザソース                       | After Effects、Premiere                                  |
| HEVC Alpha  | macOS のシステムデコーダー、Safari、Mac 版 Final Cut / AE | Windows 版 After Effects、Premiere、システムのプレーヤー |

Windows で編集する場合は ProRes 4444（内蔵プリセット「アルファ保持 · ProRes 4444」）または「アルファ分離」を選んでください。アルファの保持に失敗しても、透過が黙って失われることはありません。

### 高画質化

**拡大アルゴリズム**（目標サイズは「画質」タブの「出力解像度」で設定）：

- **Lanczos**（既定）：通常の拡大縮小。速いが、やや柔らかい画になります。
- **ArtCNN**（推奨）：AI 拡大。線がよりくっきりし、元の粒状感を保ちます。GPU で動作し（NVIDIA / AMD / Intel、Vulkan が必要）、どのエンコーダーでも使えます。2 倍拡大モデルで 1080p → 4K に最適です。それ以外のサイズは 2 倍に拡大してから目標サイズに縮小します。幅と高さの両方が 1.3 倍を超えて拡大される場合だけ AI を使い、そうでなければ自動で Lanczos になります。開発機での 1080p → 4K は Lanczos の約 80% の速度でした。**透過付きの素材にはおすすめしません**：アルファ保持時は Lanczos の約 3 分の 1 の速度です。モデルは C4F16（既定、推奨）と C4F32 から選べます。実測では画質はほぼ同じで、C4F32 は約 30%～40% 遅くなります。
- **RTX VSR**：NVIDIA の超解像。1～4 倍に拡大し、サイズは「VSR 倍率」で決まります。

**RTX VSR / VFG フレーム生成**は NVEncC エンコーダーでのみ使えます。選んだら、まず「このパソコンで RTX 設定を検証」をクリックしてください。VFG フレーム生成（2～8 倍）には RTX 40 / 50 シリーズの GPU と NVIDIA VFX ランタイム・モデルが必要です。どちらも現時点ではアルファ保持や独立マスクと併用できません。

VSR の「QualityLevel」：MMD のようなきれいなレンダリング映像の拡大には **4**（倍率 2）を選びます。輪郭に白いふちが出たり、シャープすぎる場合は強さを 1 から 0.5～0.7 に下げてください。8～11 はノイズ除去、12～15 はぼけ除去、16～19 はディテール補完（この 3 つは元のサイズのまま）、21 / 23 は配信の圧縮ノイズ修復で、MMD ではほとんど使いません。

### 無劣化カット

完成動画の先頭と末尾の音声フェードに対応します。区間のつなぎ目にはフェードをかけません。

1 本または複数の動画を区間に切り分けて前後につなげます。映像はパケット単位でコピーするので、画質は変わりません。

1. 動画をドラッグします。同じファイルから別の区間を切り出すには複製ボタンをクリックします。
2. スライダーをドラッグするか ←/→ で 1 フレームずつ確認し、↑/↓ で前／次のカット可能位置へ移動、I / O でイン点／アウト点を設定します。スマートカットがオフのときは、スライダーが最寄りのカット可能位置に吸着します。フレーム番号や時間を入力したり、「MMD のフレーム番号で入力」にチェックを入れたりもできます。
3. 音声の扱いを選んで「書き出し」をクリックします。出力名は「最初のクリップ名_trimmed」です。

- **カット位置**：H.264 / HEVC は IDR フレームでのみカットできます（「編集向け」をオンにすると約 1 秒ごと）。ProRes と UtVideo はどのフレームでもカットできます。入力した位置は最寄りのカット可能位置に吸着します。オープン GOP、VP9 / AV1、可変フレームレート（VFR）の動画には対応していません。
- **MMD のフレーム番号**：MMD から書き出したファイルは名前に `_0400-0600f` のようなフレーム範囲が付き、追加時に開始フレームを自動で認識します。その他のファイルは手動で入力できます。
- **スマートカット**（既定オフ）：入力したフレームで正確にカットし、カット位置付近の数フレームだけを元の動画のパラメーターで再エンコードします（その数フレームは劣化します）。MMDEncoder 1.5.0 以降で書き出した H.264 / HEVC が必要です。
- **音声**：元の音声を残す（サンプル単位で切り出して再エンコード）、外部の音声に差し替え、音声なし から選べます。全体の長さは常に映像と一致します。
- 別々のファイルをつなぐ場合は、エンコードパラメーターが完全に一致している必要があります。一致しない場合は違いを一覧表示し、書き出しません。

### MMD 出力プラグイン

ここでの設定はプリセットより優先されます。1.6.1 から更新した場合はプラグインも更新してください。

1. 右上の「MMD 出力」→「MMD にインストール」をクリックします（現在の Windows ユーザーにのみ登録し、管理者権限は不要です。MMD を開いている場合は再起動してください）。
2. 出力プリセットを選びます。先に「テストエンコード」を試すこともできます。
3. MMD で ファイル → AVI 出力 を開き、ビデオ圧縮で「MMDEncoder」を選んで通常どおり出力します。

完成動画は AVI のパスと同じ場所に同じ名前で保存されます（既存のファイルは上書きしません）。レンダリング後に音声を自動で合成し、仮の AVI を削除します。MMD 側の「詳細設定」からプリセットやオプションを変更することもでき、両者は同期します。

「詳細設定」の「テストエンコード」は、そのウィンドウに表示中のプリセットとオプションを使い、成功・失敗の結果を表示します。テストではオプションを保存しません。「OK」で保存、「キャンセル」で元の設定のままになります。

- **音声**：0 フレーム目から書き出す場合は AVI の音声を使います。それ以外のフレームから始める場合は、プロジェクト（.pmm）の WAV から該当部分を自動で切り出します。プロジェクトは事前に保存しておく必要があります。
- **解像度とフレームレートを MMD に合わせる**（既定オン）：MMD で設定したサイズとフレームレートを使い、その他はプリセットに従います。
- **アルファマスク**：書き出さない／同時に書き出す／マスクのみ。プリセット自体の設定より優先されます。
- **フレーム範囲の付加**（既定オン）：ファイル名に `_0400-0600f` を付け、無劣化カットで MMD のフレーム番号を使って位置を指定しやすくします。
- **予期しない中断**：MMD がクラッシュしたり閉じられたりしても、書き出し済みの部分は残ります。次に MMDEncoder を開いたときに続きを完成させるか削除できます。
- **NVEncC / RTX**：NVEncC プリセットに対応します。プリセットの解像度、フレームレート、RTX 超解像／フレーム生成を使うには「解像度とフレームレートを MMD に合わせる」をオフにしてください。オンのままだと MMD のサイズとフレームレートで出力します。RTX に必要な GPU、ランタイム、アルファの制限は動画エンコード画面と同じです。
- 64 ビット版 MMD のみ対応。プラグインは `%LOCALAPPDATA%\MMDEncoder\mmd-plugin` にインストールされ、MMD のフォルダーは変更しません。MMDEncoder のフォルダーを移動した場合は、一度開き直せば十分です。ログは「MMD 出力」から開けます。

### 音声・映像の抽出と結合

音声のフェードイン／アウトに対応します（元の音声トラックをコピーする場合は使えません）。

音声の一括書き出し（WAV / FLAC / AAC / MP3 / Opus、または元のトラックのコピー）、音声トラックの削除、外部の音声への差し替えができます。映像は再エンコードせず、MP4 または MKV で出力します（MP4 に入らない場合は自動で MKV にします）。AAC / MP3 / Opus は既定で元のビットレートに合わせます。WAV / FLAC では Hi-Res（24-bit、48 kHz 未満はサンプルレートを 2 倍。アップサンプリングで音質は良くなりません）を選べます。

## 内蔵プリセット

| プリセット                     | エンコード                           | 解像度           | 用途                                   |
| ------------------------------ | ------------------------------------ | ---------------- | -------------------------------------- |
| 標準 4K / 1080p · ハードウェア | H.264 NVENC p4、CQ 29、AAC 320k      | 長辺 3840 / 1920 | Bilibili、Douyin、YouTube などへの投稿 |
| 標準 4K / 1080p · ソフトウェア | x264 medium、CRF 21、AAC 320k        | 長辺 3840 / 1920 | 同上、NVIDIA GPU がない場合            |
| アルファ保持 · ProRes 4444     | ProRes 4444、量子化 12、PCM、MOV     | 元の解像度       | AE / PR で透過をそのまま読み込む       |
| アルファ分離 · H.264 MP4       | H.264 NVENC CQ 19 ＋ `_alpha` マスク | 元の解像度       | 最も小さい透過付き編集素材             |
| 編集素材 · ProRes 422 HQ       | ProRes 422 HQ、量子化 12、PCM、MOV   | 元の解像度       | 透過が不要な編集素材                   |

「長辺」指定の拡大縮小は横長・縦長を自動で判別します（1920×1080 → 3840×2160、1080×1920 → 2160×3840）。内蔵プリセットは名前の変更、更新、非表示、復元ができます。パラメーターの根拠は [docs/平台上传预设.md](docs/平台上传预设.md)、速度と画質の実測は [docs/编码器实测对比.md](docs/编码器实测对比.md) にあります（いずれも中国語）。

## ソースからのビルド

Node.js 22 以降、pnpm、Windows x64 が必要です。

```powershell
pnpm install
pnpm build             # 型チェックと UI のビルド
pnpm start             # 開発版を起動
mmd-plugin\build.cmd   # MMD 出力プラグインをビルド（VS 2022 C++ ビルドツールが必要）
pnpm package           # ポータブル版をパッケージ化
node scripts/zip-portable.mjs
```

圧縮スクリプトは、フルパッケージ `MMDEncoder-x.y.z-win-x64.zip`、アプリパッケージ `MMDEncoder-x.y.z-app.zip`、それぞれの `.sha256`、`MMDEncoder-x.y.z-update.json` マニフェストを生成し、両パッケージを展開して `resources/app` が完全に一致することを確認します。同じバージョンのファイルが既にある場合は `--replace` の明示が必要です。隔離した受け入れテストでは、`MMD_PACKAGE_DEST` で新しいポータブルフォルダーを、`MMD_ARCHIVE_DEST` で別のアーカイブフォルダーを指定できます。

自動更新は、Electron のバージョンが同じならアプリパッケージだけをダウンロードします。実行環境が合わない、マニフェストがない、またはアプリパッケージが検証に通らない場合はフルパッケージを使います。アプリパッケージは `resources/app` だけを、フルパッケージはプログラムフォルダーを置き換えます。どちらも `data` を保持し、失敗時は元に戻し、ログを `data/logs/update.log` に残します。

テスト（`MMD_TEST_TOOLS_ROOT` にエンコードツールのフォルダーを指定）：

```powershell
node --test tests/*.test.cjs     # 単体テストと実エンジンテスト
node tests/desktop.mjs           # デスクトップのワークフロー
node tests/desktop-tools.mjs     # ツールのインストールと設定画面
node tests/desktop-recovery.mjs  # エラーからの復旧と再起動
node mmd-plugin/tests/e2e.mjs    # MMD 出力プラグイン
```

コード構成：`backend/`（エンコードコマンド、ツール、タスクサービス）、`desktop/`（Electron メインプロセス）、`src/`（React UI）、`mmd-plugin/`（C++ DMO エンコーダー）、`tests/`、`scripts/`、`assets/`（アイコン、7-Zip、ArtCNN シェーダー）、`docs/`（更新履歴、サードパーティー表示、実測）。
