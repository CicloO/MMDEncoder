- 长时间压制时记录日志的开销更小。
- 首次启动和“重新检测”编码器稍快：CPU 编码器同时检测。
- 音频对齐窗口读取长音频更快、占用内存更少。
- 关闭对齐窗口或更换参考音频时，停止还在进行的读取和对齐，并释放音频占用的内存。
- 无损剪辑：同一个文件再次加入时不再重新读取。
- 输出到不支持硬链接的盘（如 exFAT 移动硬盘）时，压制完成后复制成品不再让界面卡住。

# 1.5.1

### 新功能

- “RTX 增强”分页改名为 **超分补帧**，新增“放大算法”：Lanczos（默认）、**ArtCNN**（AI 放大，推荐）、RTX VSR。ArtCNN 让线条更清晰，同时保留原有的颗粒质感；在显卡上运行（需要支持 Vulkan），任何编码器都能用，目标尺寸仍在“画质”的“输出分辨率”里设置。
  - ArtCNN 是 2 倍放大模型，1080p → 4K 效果最好；其他尺寸先放大 2 倍再缩放到目标。宽、高都要放大超过 1.3 倍才会用到 AI，否则自动改用 Lanczos，并在任务日志里注明。
  - 不建议用于带透明通道的素材：透明通道本身仍用 Lanczos 放大，速度只有 Lanczos 的三分之一左右，界面上会提示。
  - 本机实测（NVIDIA 显卡，1080p → 4K，NVENC 编码）：普通视频约 108 fps（Lanczos 约 132 fps），MMD 的 RGB 素材约 95 fps，保留 Alpha 输出 ProRes 4444 约 18 fps（Lanczos 约 60 fps）。带透明的测试素材放大后，亮度和 Alpha 的平均值与 Lanczos 相差不到 0.3%。AMD、Intel 显卡尚未实测。
  - 能否运行 ArtCNN 会随编码器检测一起保存；更新显卡驱动后，点“重新检测”会重新检查。

### 优化

- 使用 NVEncC 编码（包括 RTX VSR、VFG）时不再生成预处理视频文件：FFmpeg 处理好的画面直接交给 NVEncC。以前 1080p 每秒约写 25 MB、4K 带 Alpha 每秒约写 215 MB；成片与以前逐字节相同，本机实测速度持平或更快（VSR 快约 12%，VFG 快约 50%）。“复制命令”生成的脚本会检查两端程序的结果，需要用 PowerShell 7 运行。
- “验证本机 RTX 设置”按钮只在启用 RTX VSR 或 VFG 时显示，验证结果显示在按钮旁边。
- 内置预设“ProRes 422 HQ · 剪辑素材”改名为“剪辑素材 · ProRes 422 HQ”，和其他预设一样用途在前、格式在后。

### 修正

- 没有标注色彩矩阵的 YUV 视频（很多 MMD 成品和网络视频都是这样）改为按 BT.709 读取。以前按 FFmpeg 默认的 BT.601 处理后再转成 BT.709，颜色会偏（实测亮度偏暗约 5 级，红色等饱和色更明显）。

# 1.5.0

### 新功能

- 新增 **无损剪辑** 页：把视频分段裁切后首尾相接，视频逐包复制、不重新压制，画质完全不变。
  - 入点和出点吸附到能无损切开的位置（H.264 / HEVC 的 IDR 帧；ProRes、UtVideo 每一帧都可以），界面同时显示输入值和实际值。
  - 可以输入帧号、时间，或按 MMD 帧号（30 FPS 时间轴）定位；←/→ 逐帧，Shift+←/→ 跳到上一个 / 下一个可切位置，I / O 设入点 / 出点；同一文件可以切多段。
  - 音频可以保留原音频（按采样点精确截取后重新编码，接缝不做淡入淡出）、替换为外部音频（可设偏移）或不要音频，总长度始终与视频一致。
  - 不同文件的片段需要编码参数完全一致，否则列出不同之处、不导出；开放 GOP 的关键帧、VP9 / AV1、可变帧率（VFR）视频等无法保证结果正确的情况直接拒绝并说明原因。导出后核对总帧数，不对就不保留结果。
  - 导出可以取消；导出期间不能同时压制、检测编码器、管理工具或安装更新，退出软件前会确认。
- 无损剪辑的 **智能剪切**（默认关闭）：按输入的帧精确切开，只有切点到最近关键帧之间的几帧用原片的编码参数重新编码，其余直接复制；重新编码后核对编码参数集与原片一致，不一致就不导出。需要 MMDEncoder 1.5.0 起导出的 H.264 / HEVC（文件里记录了编码参数），本机编码器须与导出时相同。
- MMD 导出的文件名加上 MMD 帧范围，如 `场景_0400-0600f.mp4`（默认开启，按实际导出的帧计算；“MMD 导出”和 MMD 的“詳細設定”里都可以关闭）。起始帧和编码参数也写进文件信息里。
- 无损剪辑按 MMD 帧号输入时，从片段的起始 MMD 帧算起：MMDEncoder 导出的文件自动识别（文件信息或文件名里的帧范围），其他文件可以手动填写。
- “高级”分页新增 **剪辑友好**（默认关闭）：GOP 间隔为自动时改为每秒一个关键帧，方便之后无损裁切。实测 4K MMD 画面在恒定质量下，硬件编码约 +2%，软件 H.264 约 +5%，软件 HEVC 约 +2.6%；手动设置了 GOP 间隔时以手动值为准。

### 优化

- 添加视频快了很多：检查是否可变帧率改为读取前 120 帧的时间戳，不再解码画面。实测 4K 素材 3.4 秒 → 0.4 秒（UtVideo）、4.4 秒 → 0.15 秒（ProRes）、1.1 秒 → 0.12 秒（H.264）；没有时间戳的文件仍按原方法解码检查。
- 软件编码的 HEVC（x265）改为闭合 GOP：以前用的是 x265 默认的开放 GOP，成片除开头外无法无损裁切。实测体积只多约 0.1%~0.4%，画质和速度不变。
- 一次选中同一 PNG 序列的很多张图片时，文件夹只读取一次。
- MMD 插件“詳細設定”的选项去掉了括号里的说明。

### 修正

- 修正自动更新：多次还原失败时保留的 `.update/old-2`、`old-3` 等旧版文件可能被删掉，现在都会保留。

# 1.4.3

- 新增 **Hi-Res 音频** 选项（音视频提取与合并页，以及视频压制页“音频”分页，可存进预设，MMD 导出也会按预设输出）：输出 WAV / FLAC 时统一为 24-bit，源低于 48 kHz 时升到 2 倍采样率（44.1 → 88.2 kHz），48 kHz 及以上保持原采样率；32-bit 与浮点源加抖动降为 24-bit；源已是同格式 24-bit 时直接复制。合并时按替换音频本身的参数计算，输出 MKV；视频压制页选 FLAC 或 PCM 时可勾选，PCM 输出 24-bit（MOV / MKV），勾选时 MP4 自动改为 MKV。当前 FFmpeg 带 soxr 时用 soxr 重采样。升采样不会提高音质，平台的 Hi-Res 判定尚未实际上传验证。
- 修正 MMD 导出：工程 WAV 或 AVI 音轨比渲染的画面短时，成片会被截短到音频长度（例如 3 秒画面只剩 1 秒）。现在以渲染的画面为准，音频不够补静音、多了截掉；导出起点已超过 WAV 结尾时成片不带音频；合成后核对帧数，不全就保留原视频并报错。
- 修正自动更新：“重启并完成更新”后软件可能打不开（重启时沿用了更新程序的 Node 模式）。
- 修正自动更新：上次更新还原失败时保留的旧版文件（`.update/old`），会在下一次下载更新时被删掉。现在任何下载、失败和安装都不会动它。
- 修正音视频页：处理中从队列移除的等待文件仍会被处理。视频队列同样处理。
- 修正更换编码工具位置时中途失败（文件被占用、没有权限等）会让工具“消失”：现在先移动工具、最后移动清单，失败时全部移回原位置；只有清单、没有工具的文件夹不再被当作已有安装。
- MMD 导出插件：MMDEncoder 30 秒没有回应时插件会按时放弃，不再让 MMD 一直卡在开始导出（以前可能无限等待）。需要更新插件。
- 音视频页处理时，界面更新只带每个文件日志的末尾，完整日志在展开“实际命令与日志”时读取，长队列更流畅。
- 开发：格式检查不再读取 `tests` 里的大型实测视频；修正 `UX-CONTRACT.md` 中与现状不符的描述。

- 新增 **PNG 图片序列** 导入：把装有序列的文件夹拖进视频队列，或在“添加视频”里选其中任意一张 PNG，按 `name_0001.png` 这样的连续编号作为一段视频压制。帧率在“当前素材”的“序列帧率”里选（23.976–120，默认 30），带透明的 PNG 可以保留 Alpha 或分离遮罩；序列缺帧时提示缺第几帧，不会悄悄截短。

- 更新后，如果新版改动了你修改过的内置预设，打开软件时会弹窗询问：用新版覆盖，或把你的版本另存为个人预设（以前会直接丢弃你的修改）。
- MMD 导出插件的日志新增耗时统计：准备时间、渲染时长与帧率、MMD 等待编码器的累计时间与占比（以及单帧最长等待）、最后一帧后编码器收尾时间，用于判断编码是否拖慢了 MMD。
- MMD 导出插件的注册指向已不存在的文件时，“MMD 导出”会提示“插件需要修复”并提供“修复插件”按钮；更新插件时保留上一版插件文件，卸载时即使插件文件已丢失也能清掉注册信息；安装、卸载和插件注册都会记录到 `%LOCALAPPDATA%\MMDEncoder\mmd-plugin\logs\install.log`，便于排查。
- 实测文档新增 ProRes 量化与 H.264 CQ 的大小、画质对比（第 7 节）。
