- MMD 导出不再检查遮罩是否全白或全黑，遮罩总会保留，由用户自己判断：这项检查在 4K 下比片长还慢（6.7 秒的片段要 8.5 秒），去掉后收尾快约 8 秒。

- MMD 导出插件的日志新增耗时统计：准备时间、渲染时长与帧率、MMD 等待编码器的累计时间与占比（以及单帧最长等待）、最后一帧后编码器收尾时间，用于判断编码是否拖慢了 MMD。

- 实测文档新增 ProRes 量化与 H.264 CQ 的大小、画质对比（第 7 节）。
- MMD 导出的“同时导出 Alpha 遮罩”改为三选：不导出 / 同时导出遮罩 / 仅导出遮罩，MMDEncoder 的“MMD 导出”和 MMD 的“詳細設定”里都有。这里的选择优先于预设自带的遮罩设置；选中自带遮罩的预设时自动切到对应选项。在 MMD 里保存的选择会立即反映到 MMDEncoder。
- MMD 导出意外中断（MMD 崩溃或被关闭）时，已导出的画面不再丢失：下次打开 MMDEncoder 会提示，可以在“MMD 导出”里补完（合成音频、改回正式文件名）或删除。
- 每次 MMD 导出都按开始时的预设和选项完成。以前渲染途中在 MMDEncoder 里换预设，收尾合成音频会用新预设的设置，可能失败（例如把 PCM 音频放进 MP4）。
- MMD 导出收尾时，如果渲染期间出现了同名文件，改存为“名称 (2)”，不再覆盖。
- 黑白遮罩的编码速度档由 medium 改为 veryfast（WebM 的 VP9 不变）：实测 4K 遮罩编码快约 30%，文件大约 7%，仍为无损。

- “MMD 导出”显示上次导出的耗时：准备、渲染（含帧率）、等待编码器的时间与占比、编码收尾、合成音频，并说明编码是否拖慢了 MMD（需要新版插件）。
- MMD 的“詳細設定”新增“打开 MMDEncoder”按钮（已打开时切到前台），方便管理预设、补完中断的导出。
- “测试编码”在编码器启动失败或中途退出时不再卡住；60 秒未结束会自动停止。
- 压制时进度更新最多每 200 毫秒发送一次，任务日志不再随每次进度传给界面，长队列时界面更流畅。
