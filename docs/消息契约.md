# 消息契约

多语言准备 A3。实现位于 `locales/messages.mjs`（纯数据与格式化）、`backend/errors.cjs`（中文诊断回退）和 `backend/worker-protocol.cjs`（进程错误分帧）。

## 错误与校验

程序自有业务错误使用稳定 `code`、可 JSON 序列化的 `params` 和诊断回退 `message`。参数可以是 JSON 标量、数组或对象，传递给编码器的数值序列化不受显示语言影响。外部错误可能没有业务 code；其原始 message 必须保留。

```json
{
  "code": "VALIDATION_FAILED",
  "params": {},
  "message": "请检查以下设置",
  "issues": [
    {
      "code": "ALIGN_TOO_SHORT",
      "params": { "seconds": 1 },
      "message": "自动对齐失败：音频太短，至少需要 1 秒"
    }
  ]
}
```

`validationIssue()` / `validationError()` 保留每项数据，不在核心层把问题拼成一段中文。显示层逐项格式化；未知问题码使用该项 message。Electron 通过成功返回的 `__mmdError` 数据封套传递，`src/ipc.ts` 重建 Error 时保留 issues，不能依靠 contextBridge 传递被拒绝 Error 的自定义属性。

## 阶段与历史摘要

阶段使用 `stageDescriptor("copying_segment", { current: 2, total: 5 })`，结果为 `{ stage, params }`；任务 status 继续使用原有稳定 ID。显示层 `stageMessage()` 查 `stage.<ID>`。

摘要使用 `summary(code, params)` 或 `messageDescriptor(code, params, fallback)`，保存 `{ code, params, message }`；显示层 `summaryMessage()` 查 `message.<CODE>`。换语言只重新格式化，不重写记录、状态或任务。未知阶段回退可用 message / stage ID，未知摘要码回退原始 message；已有纯字符串记录原样显示，不匹配旧中文。

这些构造和格式化接口已定义并验证 JSON 往返。A3 尚未把全部既有队列和历史的生产方替换为新格式；逐模块迁移时要一起修改消费方，不能仅修改字段类型。

## 音频 worker 的字节通道

- 输入继续由 `MMD_ALIGN_JOB` 提供。preview 成功 stdout 是原始 mono 16-bit PCM；align 成功 stdout 是原来的对齐结果 JSON。
- 失败退出码为 1，stderr 写 `MMDENCODER_ERROR_V1 ` + 一行 JSON 错误数据 + `\n`。JSON 内的换行必须转义，不能把错误对象写进 PCM 字节流。
- 父进程使用 StringDecoder 解码任意切分的 UTF-8 字节，再按行识别标识。完整错误记录与最多 4000 字符的诊断尾部分开保存，避免截断大 JSON 后丢失 code / 参数。其他 stderr 诊断并入 detail；损坏的标识记录仍作为原始诊断保留。
- 原有超时、同 slot 替换、显式取消和 stdin 关闭的生命周期不变；取消由进程状态 / 稳定 code 判定。原始 FFmpeg / 操作系统诊断保留原文。

验收入口：`tests/i18n.test.cjs`（问题列表、阶段 / 摘要、IPC 和未知码）、`tests/worker-protocol.test.cjs`（字节切分、长记录、真实 worker 的 PCM 与失败）、`tests/align-lifecycle.test.cjs`（取消和进程结束）、`tests/desktop-locale.mjs`（真实 worker → Electron → preload → 前端 invoke）。
