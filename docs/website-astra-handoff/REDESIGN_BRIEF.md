# MMDEncoder 官网 — Astra 视觉与交互重构任务书

> 工作分支：`design/website-astra-redesign-20261023`  
> 仅在 `docs/website-astra-handoff/` 内实施官网重构。不要修改软件本体、构建流程或仓库根目录的 Vite `index.html`。

## 任务目标

不要只微调现有“长胶卷”的曲线。基于 `index.html` 的完整内容、三语言与交互，重新构思并实现一个更成熟、精致、有实验性而非模板感的 **MMDEncoder 白昼产品官网**。目标访客为 MMD 动画创作者、剪辑/调色/合成人员及熟悉编码的技术用户。网站的任务是快速说明：这是什么工具；支持什么实际工作流；为何适合 MMD；有哪些限制；如何下载。

**当前主要问题**：长胶卷像一条固定宽度、固定图案的 SVG 轨道贴在整页上；胶卷与内容没有充分的结构关联。亮蓝、淡紫、卡片、贴纸、刻度较密，局部偏活泼且形式重复；页面垂直很长，视觉主次和留白没有被充分利用。即使布局有错位，章节节奏仍可更精确、更大胆。

## 设计主张

建议从 **「数字影像编辑台 × 独立设计工作室」** 出发，但允许有更好的创意方向。核心意象是**帧、时间、轨道、片段、编码输出**，而不是通用的科技粒子、抽象玻璃卡片、霓虹渐变。

从下列可能性中推导真正独特的设计，不必机械全用：

- 胶卷是叙事线索：在首屏局部显影，在功能区过渡为刻度/时间线，在 MMD 区与“非 0 帧起始依然有音频”的工作流发生呼应，在结尾成为收束的帧/片尾，而非一根从头到尾等粗的“软管”。
- 胶卷的角度、宽度、齿孔密度、曝光区域，应有**视觉因果关系**。可以跨越区块、在裁切后重新进入，但每一次出现都承担构图任务。不要简单绘制一根可见的“无限长曲线”。
- 时间码（如 00:00:00:00）、FPS、输出格式、帧范围与刻度线，在**信息真实、位置有意义**时使用；不要每章复制一套虚构的相同时间码数据。
- 节奏：首屏大胆但简洁；功能可采用一大两小、水平长幅、留白区、窄注释栏、章节跨线排版。用“不规则但有隐形栅格”的系统让页面显得自由，而非无序。
- 文字排版：中文主体有出版设计感；Latin/数值/帧码用紧致的技术字体。醒目的中文标题、短引言、精确功能说明。字距、留白、对齐、行高都要逐屏检查。
- 视觉调性：继续白天模式，以清透近白为底色、浓色文字与节制的品牌蓝为核心；低饱和层次和少量点睛色即可。降低大面积泛紫渐变、阴影、贴纸和四处浮动的小标记。
- 必须有更高级的动效：视差仅用于有意义的层级、胶卷的帧位移与阅读进度关联、章节入场具有节奏、hover 带反馈、画面对比可拖动。让动画衔接叙事，避免每个组件都乱飘。**宁可做 3 个高质量连贯动效，也不要 20 个机械动效**。

## 必须保留的内容与能力

以 `CONTENT_ZH.md` 和当前 HTML 中中文专业文案为基础，核对仓库根目录 `README.md` 的技术事实。下列能力不可遗漏或夸大：

1. 批量压制 H.264 / HEVC / AV1 / VP9 / ProRes，软硬件编码、队列、预设。
2. ArtCNN（Vulkan）、RTX VSR / VFG 的不同硬件与编码器适用边界，不能默认所有显卡都支持 RTX 功能。
3. Alpha 保留/分离黑白遮罩/仅遮罩/绿幕；Windows AE 等后期环境推荐 ProRes 4444 或分离遮罩；不承诺所有播放器和平台都兼容。
4. 片段裁切与拼接的无重编码限制（IDR、帧级格式、智能剪切的局部重新编码）。
5. MMD 直接导出插件：MMD 中 AVI 输出选择 MMDEncoder，预设直出；**非 0 帧起始也能有音频**，前提是已保存的 PMM 工程和关联 WAV 文件可访问，按帧范围截取、再合成。**只支持 64 位 MMD，插件目前不支持 NVEncC 预设**。不同于主程序的能力不能混为一谈。
6. Windows 10 / 11 x64，便携版与首次安装编码工具的步骤。
7. 下载按钮真实链接到 `https://github.com/CicloO/MMDEncoder/releases`，源码与文档入口真实有效。

现有三个语言 `zh-CN` / `ja` / `en` 的翻译、手动语言切换、选择持久化、访问者 IP 所属国家映射、浏览器语言降级逻辑均保留。**中文内容语义为基准**。需要同步翻译你新加/调整的标题和说明，避免中日英文功能描述有差异。

演示是设计模拟，不得用虚构基准成绩、测量数字、真实用户评价或假装真的是处理前后实测。必要处明确注明示意用途。

## 具体实现要求

- **当前实现**：`docs/website-astra-handoff/index.html`，单文件 HTML/CSS/JS。允许重构 DOM/CSS/SVG/JS 结构，但最终仍需离线可打开，不依赖在线前端运行时或 CDN。
- 若引入动画库，须内嵌或可随包离线运行；优先原生 Web Animations API、CSS、IntersectionObserver、SVG，减少不必要依赖。
- iOS Safari 不得产生蓝色箭头 Emoji / 绿色星形 Emoji 等系统字体替换；装饰性符号统一内联 SVG 或 CSS 绘制，不用容易被 emoji 化的 Unicode。
- 所有文案默认可见。动画不能依赖 JS 才显示正文；低端机、JS 禁用、IntersectionObserver 失败时仍能阅读。尊重 `prefers-reduced-motion`。
- 性能：滚动主要修改 `transform` / `opacity`，避免每帧读取全页面布局并修改数百个节点；监测 FPS/滚动卡顿，限制 SVG 齿孔和 DOM 数量；防止手机 100vh 抖动；无需持续占用高 CPU。
- 针对 320 / 390 / 768 / 1440px 宽度实际检查（iPhone Safari 优先）：无水平溢出、标题不溢出、菜单可点、触控交互舒适、胶卷不能盖住主体文字。
- 跳过重复统一式卡片排布。避免首页过度挤满“虚拟软件界面 + 小标签 + 花纹”。页面留白要有韵律。
- 若设计新信息分区，保持内容准确且不要删掉 FAQ/安装/插件兼容性。
