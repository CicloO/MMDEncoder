# 多语言准备

当前界面仍为简体中文。准备工作按开发计划分批实施，不提供只有中文一个选项的语言选择器。实施进度和验收门槛见 [多语言准备实施记录](多语言准备实施记录.md)。

**目标语言**：简体中文（源语言）、日本語、English。**顺序**：先完成准备（全部文字集中到 `locales/`、错误和阶段改为稳定的码、语言切换与回退、检查工具、插件文案），再统一翻译日语和英语，最后逐页检查三语排版（长文案、按语言选字体、插件窗口）。准备阶段不写日英译文。

`locales/zh-CN.json` 是已迁移文字的唯一来源，前后端和便携包共用。`src/i18n.ts` 提供有类型的 `t(key, params)`；参数用 `{name}`，按纯文本替换。`BackgroundColor` 已迁移完整的可见文字与无障碍名称。

后端 `appError(code, params)` 创建稳定错误码并保留中文消息供尚未迁移的调用方使用；`align-service.cjs` 的业务错误已经迁移。引擎原始诊断保留在 `ALIGN_FAILED` 的 `detail` 参数里。下一步可逐模块迁移，避免按中文消息判断业务类型。

Electron 会丢弃被拒绝 Error 的自定义属性，因此 `desktop/actions.cjs` 将错误序列化为 `__mmdError: { code?, params?, message }`。`preload.invokeResult` 按数据返回；迁移后的前端用 `src/ipc.ts` 的 `invoke()` 在渲染进程重建 Error，并按错误码显示文案。未知错误码退回原始消息。已有 `window.encoder.invoke()` 继续返回结果或拒绝消息。音频对齐窗口和自动对齐已使用新入口。

运行 `node scripts/i18n-scan.mjs` 查看 `src/`、`backend/`、`desktop/`、`mmd-plugin/src/` 四层清单；加 `--json` 输出完整文字、文件、行列、字面量类型和分类。JS / TS 使用语法树统计含汉字的字符串、模板片段和 JSX 文本，不计注释。C++ 使用独立词法扫描，覆盖宽字符串、相邻字面量、转义和 raw string，同时保留 ASCII 字符串，避免漏掉原生控件与编码器名称。相邻 C++ 字面量分别列出，迁移时需要按完整句子合并。

分类值为 `interface`（界面）、`business`（业务消息）、`diagnostic`（诊断）和 `technical`（技术值）。自动建议不等于人工审校，也不自动排除任何条目。`scripts/i18n-exceptions.json` 按精确的文件与原文记录已审阅分类及理由，禁止整文件忽略；例外仍显示在清单中。缺少理由、重复或已失效的例外会使扫描失败。只有已审阅的诊断 / 技术值标为 `excluded`，不代表它们可以从清单消失。

清单不是翻译覆盖率：JS 的纯 ASCII 文字需要在逐页迁移时复核，用户输入、输出名称、技术 ID 与诊断也必须结合消费方判断。已集中到 `locales/` 的文案不计入扫描数量。运行 `node --test tests/i18n-scan.test.cjs` 验证清单工具。

新增或迁移一个模块时，同步迁移可见文字、无障碍名称和业务错误，添加语义 key 和稳定错误码；保留未知错误回退，再运行类型检查、相关测试和桌面验收。按模块推进，不按字符串批量替换；准备完成前不新增日英译文。
