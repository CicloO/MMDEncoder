# 多语言准备

当前界面仍为简体中文。准备工作按开发计划分批实施，不提供只有中文一个选项的语言选择器。实施进度和验收门槛见 [多语言准备实施记录](多语言准备实施记录.md)。

验收按用户最新决定采用“模块定向验证、大阶段完整回归”。纯拆分仍独立提交并先验证受影响职责，跨模块变更补相关联动；B2–B6 各阶段收尾及最终交付前运行完整清单，不为每个小提交重复全套或无关硬件检查。

2026-10-26 模块化补充：R0 先判断职责、依赖及实际维护成本，可以得出“不需要拆分”。内聚且接口稳定的较大文件可保留，不按函数、状态或组件机械拆分；相关且经常共同修改的代码尽量放在一起。结构调整包含必要的合并，与功能分开提交和验证；不引入无用抽象、循环依赖、重复状态或复杂传参，已有拆分也须复查。无需调整时不造空提交，完成拆分不是目标。

**目标语言**：简体中文（源语言）、日本語、English。**顺序**：先完成准备（全部文字集中到 `locales/`、错误和阶段改为稳定的码、语言切换与回退、检查工具、插件文案），再统一翻译日语和英语，最后逐页检查三语排版（长文案、按语言选字体、插件窗口）。准备阶段不写日英译文。

`locales/zh-CN.json` 是已迁移文字的唯一来源，前后端和便携包共用。`src/i18n.ts` 提供有类型的 `t(key, params)`；参数用 `{name}`，按纯文本替换。`BackgroundColor` 已迁移完整的可见文字与无障碍名称。

## 已实施的语言基础（A2）

- `locales/registry.json` 是正式语言注册表，目前只注册 `zh-CN`。中文不随 Windows 语言自动改变。
- `backend/preferences.cjs` 只负责归一化和解析语言偏好；service 通过已抽离的 `settings-store.cjs`，将 `preferences.locale` 保存在原有 `settings.json` 中。它不属于编码 settings、预设或 RTX 签名。`null` 为后续“跟随系统”保留，目前仍解析为中文；不支持的值回退中文。
- `setLocale({ locale })` 先保存，成功后广播 `state.locale` 和 `state.preferences`。写入失败回滚内存，不广播未保存的选择。此入口不触发编码检测或任务重启，正式界面暂不提供选择器。
- `locales/runtime.mjs` 是不依赖文件、DOM 或进程的共享运行时。支持具名插值、按 `count` 选择 `one` / `other`、缺失或空译文回退中文、订阅以及 `Intl` 数字 / 日期 / 单位 / 文件大小格式化。调用方提供语言资源，新增语言时在统一入口注册。
- `src/LocaleRoot.tsx` 读取初始状态并订阅 IPC 更新；刷新已打开的 React 树，不通过 key 重新挂载。它同步 `html.lang`、标题，保留编辑状态。模块级选项保存 key，在渲染时获取文字；背景色样板已按此调整。其他未迁移页面仍有中文常量，A2 不能代表全界面覆盖。

`node --test tests/locale.test.cjs tests/locale-encode.test.cjs` 验证回退、单复数、订阅、持久化 / 重启、保存失败和真实编码中的设置 / 命令稳定性。`node tests/desktop-locale.mjs` 单独构建测试样板，验证标题、静态选项、缺失 key、无障碍名称、未保存输入、键盘和窄窗口；正式应用的 preload / IPC 也在该测试中验证。测试语言只存在于 `tests/fixtures/i18n/`，测试构建输出至 `verification/`，不进入 `locales/`、`dist/` 或便携包。

## 共享显示与预设（B1）

`src/presentation.ts` 的状态、音频选项、淡入淡出选项与说明在渲染时取文案；调用方使用 `statusLabel()`、`audioLabels()`、`fadeOptions()`、`fadeHint()`。数字、时钟式时长与文件大小使用当前 locale 的 Intl 格式；大小仍按 1024 换算，单位采用 Intl 的写法（如中文 `kB`）。未知状态保留原始技术值，不能根据显示文字判断状态。编码器 ID、参数、音频选项值和淡入淡出秒数保持技术值。

`backend/definitions.cjs` 持有原有纯定义，`locales/builtin-presets.json` 将稳定内置 ID 关联到默认名称 key。`name` 与 `settings.presetName` 继续保存原名称；`nameKey` / `nameSource` 只用于显示投影，`settingsEdited` 与名称来源分开，`edited` 保留既有总修改标记。渲染使用 `presetLabel(p, peers)` / `engineLabel(e)`，不把译名送回 save / rename / apply 或命令构建。

新保存的内置覆盖带 `nameSource`：只保存参数时沿用原来源；显式改名标为 `user`，即使文字恰好等于当前中文默认名。旧覆盖没有改名意图，不能从 `edited` 或中文相等推断，因此其保存名称一律保守视为用户内容；它们不会自动获得译名。个人预设、旧历史、输出模板及用户文件名始终保留原文。改名输入框编辑的是保存名，不能预填译名后意外写回。

重名检查仍比较实际保存名、沿用原大小写规则，与界面 locale 无关。多个默认译名重合或碰到用户名称时，只在默认显示名旁补稳定 ID 区分；用户名称不变。按用户 2026-10-26 的新决定，程序新生成的保存名冲突后缀用固定英文 ` (Built-in)`、` (Modified)` / ` (Modified 2)`，独立标记继续本地化内置预设的显示。已有用户名称不重写，内置定义和指纹不变；添加译文或切换 locale 不触发预设更新冲突。

预设管理错误使用 `PRESET_*` code / params，公共请求层保留错误描述，App 在渲染时格式化错误与结构化通知。核心参数校验的细项仍由后续 B2 迁移，当前保存为可读 detail，不能把 B1 记作所有校验已迁移。预设管理外围的确认 / 保存 / 导入导出窗口文字仍按 B5 迁移。

插件配置为每项写入独立 `displayName`；原始 `name` 和 `settings.presetName` 不变，helper 继续消费这些原值。DLL 下拉框优先显示 `displayName`，旧配置缺失它时回退 `name`。共享显示函数位于 `locales/preset-names.mjs`，前端和配置生成共用，DLL 无需另一套名称映射。

验收入口：`tests/preset-locale.test.cjs` 的迁移前 SHA 快照对照全部 7 个默认预设的设置、指纹和命令；`tests/i18n.test.cjs`、`tests/desktop-locale.mjs` 验证共享显示、预设选择、用户名称、真实 IPC 错误及原位刷新；`mmd-plugin/tests/locale.mjs` 验证真实 DLL 下拉项、旧配置回退和保存 / 取消。

## 视频压制（B2）

视频设置、Alpha / RTX、队列操作、通用 / 单独设置、底部概览与兼容提示使用渲染时文案。`validateIssues()` 为核心问题列表；`validate()` 保留原中文数组转接，供后续待迁移模块使用。新调用方读取 `issues` / `errorData`，由 `errorMessage()` 分别显示，不能解析中文消息来决定修复或重试。软件重试依据后端的系统错误码结果。

命令与任务阶段携带稳定 stage / params 和中文诊断回退，显示用 `stageMessage()`。新预览返回 `summaryData`，仅保存技术值与描述；`locales/video-summary.mjs` 在显示时取得编码器标签、单位及说明。原 `summary` 字符串保留作诊断投影，前端可调用 `summaryMessage(summaryData)` 原位刷新。`videoName()` 仅格式化 PNG 序列的程序注释，用户名称和输出模板原文不变。队列通知由 `notification()` 传描述给共享 actions，不提前固定为当前语言。

`tests/settings-issues.test.cjs` / `video-messages.test.cjs` 验证真实规则的消息契约、外部诊断和系统码；桌面语言样板覆盖本次组件与长文案，未提供正式日英翻译。遮罩格式等功能单独实施；FileMeta / 音频对齐、管理窗口及插件剩余消息继续按 B3–B6 迁移。

用户在功能待办第六项改定 NVEncC 输出后，命令使用 `pipeFrom → NVEncC → pipeTo`，合并为编码与封装阶段，进度只读末段 FFmpeg 的 stdout。前段原始帧仍用 NUT；后段实测选用流式 Matroska，保留旧 MKV 的时间戳，避免 NVEncC 输出 NUT 时的首帧偏移。移除了临时 `.nvenc.mkv`、`video.nvenccHint` 和预览中的双倍磁盘说明；音频仍由末段 FFmpeg 处理。复制命令与 MMD helper 使用同一三段命令结构，任一成员失败停止整链。MMD 的 Job 仅用于显式终止，不设 `KILL_ON_JOB_CLOSE`；宿主消失时允许输入 EOF 自然收尾，保留可补完的隐藏视频。实际插件中断补完的针对性证据见实施记录，B6 仍须复验完整插件路径。

遮罩格式字段为 `maskFormat`（lossless / gpu-lossy / x264-lossy），缺省无损且不改变内置指纹。选择只在分离或仅遮罩时显示，实际编码策略由 mask-settings 根据已试编码能力与尺寸决定。命令携带 `maskEncoding`，任务回退使用 `noteData` 的稳定码，显示层在渲染时翻译，不靠“lossless”字符串猜 GPU 使用情况。运行器以超时 / 取消标记和失败进程序号区分遮罩失败与下游失败；存储、超时、取消及下游编码 / 封装失败不会误触发有损遮罩回退。正常的新尝试清掉旧说明，自动 CPU 回退保留原因。桌面语言样板验证三选、刷新与长说明；实际剪辑软件导入由用户明确暂缓，MMD 完整路径仍列 B6。

按功能待办第七项，视频音频码率只接受 64–512 kbps 的具体选项，默认 / 新个人预设为 320；不换算或兼容旧 0，命令没有 AAC 192k 或 Opus 自动码率兜底。两个旧“默认”文案键删除。两个 ProRes 内置预设的设置与指纹按用户授权更新，七个内置命令保持一致；这一差异不归因于语言迁移。音视频工具的“跟随源文件”0 含义不同，保持原行为。ArtCNN 提示改为“C4F32 慢约 30%–40%，画质差别不明显。”，超分补帧页删除两处重复小标题，原控件标签与分隔保留。

## 音视频与对齐（B3，已完成自动验收）

媒体页面、列表、表单和选项通过 `media.*` 在渲染时读取，码率 0 仍表示跟随源音轨。按用户功能决定删除视频 / 合并的 autoAlign 开关和旧保存值，载入新音频自动匹配，按任务 token / slot 取消旧结果，波形按钮动效随任务结束、失败或取消而停止，reduced-motion 时静止。AlignDialog 的请求 / PCM / 波形秒值 / 整数帧值 / busy 由 useAlignSession 拥有，按参考实际分数 FPS 计算有效偏移，无视频参考明确回退 30 FPS；busy 使用稳定 ID，取消只认 ALIGN_CANCELLED。FileMeta / MediaDetails 本地化标签与 Intl 显示，用户路径和完整 ffprobe JSON 原样保留。

media-queue / media-job 保留 errorData / metaErrorData，显示层使用 errorMessage。`MEDIA_META_FAILED`、`AUTO_ALIGN_FAILED` 和 `MEDIA_BATCH_FAILED` 的 `params.error` 保存原始错误对象；`locales/media-messages.mjs` 在显示时格式化内层错误，再插入整句，避免先把中文错误冻结为 detail。未知外部诊断保留原文，日志使用中文基准文案和实际引擎输出。

媒体完成行复用 OutputFiles，显示用时和已提交的实际文件名，不复制输出路径到额外状态。新无声视频输出后缀为 `_no_audio`、合并为 `_merged`，固定英文，不随 locale 改变。直接复制允许短音轨并保留原采样、完整视频，重新编码才补静音 / 裁到视频流长度。B3 阶段完整基线与后续序列边界修正分别记录，见实施记录。

## 固定技术命名

用户在 2026-10-26 将固定技术值统一改为英文，取代旧计划中相应“命名保持”及中文精确例外。输出后缀 `_no_audio` / `_merged` / `_trimmed`、保存框默认 `output`、缺少预设名时的输出模板替代 `Custom`、内部校验占位 `name`、codec / pixFmt 缺失值 `unknown` 和上述新生成预设名修饰都不随 locale 改变。已有输出文件、用户文件名和用户预设名称保留原文；界面标签、内置预设的可见默认名称和说明继续由中文基准表管理，后续统一翻译。外部诊断保留原始内容。未迁移的中文状态 / 错误仍按 B4–B6 转为稳定英文 ID 和文案数据，不作为新的技术例外保留。

## 错误与迁移入口

后端 `appError(code, params)` 创建稳定错误码并保留中文消息供尚未迁移的调用方使用。共享数据契约见 `locales/messages.mjs` 及 [消息契约](消息契约.md)：错误保留 code / params / message，多条校验使用独立的 issues；阶段是 stage / params；历史摘要是 code / params / message。`src/i18n.ts` 提供错误、阶段和摘要的显示层格式化。旧的纯字符串记录原样显示，未知 code 回退原消息，不通过匹配中文猜测含义。

Electron 会丢弃被拒绝 Error 的自定义属性，因此 `desktop/actions.cjs` 将错误序列化为 `__mmdError: { code?, params, message, issues? }`。`preload.invokeResult` 按数据返回；迁移后的前端用 `src/ipc.ts` 的 `invoke()` 在渲染进程重建 Error，保留问题列表并按错误码显示。已有 `window.encoder.invoke()` 继续返回结果或拒绝消息；需要可靠读取结构化数据的消费方仍使用新入口。音频对齐窗口和自动对齐已使用该入口。

音频 worker 的失败 stderr 使用 `MMDENCODER_ERROR_V1 ` 加单行 JSON 和换行；成功的 preview stdout 始终是原始 PCM，align stdout 是原有结果 JSON。协议读取器分别保存完整记录和最多 4000 字符的原始诊断尾部，按 UTF-8 流解码；不依赖进程 data 事件正好对应一行。无结构化记录、损坏记录及未知码均有可读回退。对齐算法的“音频太短”和解码失败现在直接携带稳定 code / params，父进程不用从中文 detail 还原错误类型。

A3 的契约与对齐 worker 路径不代表其他队列、核心校验和历史已经全部迁移；全量生产 / 消费迁移继续按 B1–B6 实施。

## MMD 完整样板（A4）

`src/MmdExportDialog.tsx` 的可见文字、无障碍名称、选项、状态和测试结果使用共享文案。已抽离的请求层接入 `src/ipc.ts`，错误数据保留到渲染进程；helper 的 plan / test 失败返回 `errorData` 并保留原 `error` 回退，测试成功返回 code / params / message。测试用时是参数，编码参数和选择的保存规则保持原意。

`backend/mmd-config.cjs` 统一管理配置与选择，主程序在保存语言偏好后同步插件配置。`backend/plugin-messages.cjs` 按 `locales/plugin-keys.json` 生成 43 项有限文案快照，与 locale 一起写入 `mmd-export.json`。用户预设名称、ID、编码设置原样保存；插件不建立另一套语言偏好。

`mmd-plugin/src/messages.cpp` 为一个窗口持有快照，按 code / 参数格式化 helper 结果。主程序关闭后仍可读取配置；缺失项由 `scripts/plugin-messages.mjs` 从中文表生成的编译数据回退，C++ 不手写第二份中文翻译表。`build.cmd` 自动生成该数据再编译。测试语言仅由测试注入配置，不进入源语言资源或 DLL 回退表。

原生窗口按实际字体测量长文案，必要时增加宽度和说明区高度，保留字号、控制类型与保存逻辑。测试结果仍在按钮显示简写，完整结果和失败诊断写日志。

验收入口：`tests/plugin-messages.test.cjs`、`tests/desktop-locale.mjs`、`mmd-plugin/tests/locale.mjs`。最后一项加载真实 DLL，验证主程序关闭时的测试语言、中文回退、长文案尺寸、当前选项测试、失败日志和取消 / 保存；它与真实 MMD 工程导出分别记录。原生测试会临时写实际 Known Folder 的配置，运行前关闭 MMD / MMDEncoder，结束自动恢复。

后续正式添加日英时，补充注册表和集中语言资源入口，按相同 key 与参数规则审校。A4 尚未翻译 Electron 文件框、其他业务页面和插件导出收尾等剩余路径，继续按 B 批实施。

运行 `node scripts/i18n-scan.mjs` 查看 `src/`、`backend/`、`desktop/`、`mmd-plugin/src/` 四层清单；加 `--json` 输出完整文字、文件、行列、字面量类型和分类。JS / TS 使用语法树统计含汉字的字符串、模板片段和 JSX 文本，不计注释。C++ 使用独立词法扫描，覆盖宽字符串、相邻字面量、转义和 raw string，同时保留 ASCII 字符串，避免漏掉原生控件与编码器名称。相邻 C++ 字面量分别列出，迁移时需要按完整句子合并。

分类值为 `interface`（界面）、`business`（业务消息）、`diagnostic`（诊断）和 `technical`（技术值）。自动建议不等于人工审校，也不自动排除任何条目。`scripts/i18n-exceptions.json` 按精确的文件与原文记录已审阅分类及理由，禁止整文件忽略；例外仍显示在清单中。缺少理由、重复或已失效的例外会使扫描失败。只有已审阅的诊断 / 技术值标为 `excluded`，不代表它们可以从清单消失。

清单不是翻译覆盖率：JS 的纯 ASCII 文字需要在逐页迁移时复核，用户输入、输出名称、技术 ID 与诊断也必须结合消费方判断。已集中到 `locales/` 的文案不计入扫描数量。运行 `node --test tests/i18n-scan.test.cjs` 验证清单工具。

新增或迁移一个模块时，同步迁移可见文字、无障碍名称和业务错误，添加语义 key 和稳定错误码；保留未知错误回退，再运行类型检查、相关测试和桌面验收。按模块推进，不按字符串批量替换；准备完成前不新增日英译文。
