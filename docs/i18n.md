**目标语言**：简体中文（源语言）、日本語、English。**顺序**：先完成准备（全部文字集中到 `locales/`、错误和阶段改为稳定的码、语言切换与回退、检查工具、插件文案），再统一翻译日语和英语，最后逐页检查三语排版（长文案、按语言选字体、插件窗口）。准备阶段不写日英译文。

`locales/zh-CN.json` 是程序自有界面文案的唯一来源，前后端和便携包共用。`src/i18n.ts` 提供有类型的 `t(key, params)`；参数用 `{name}`，按纯文本替换。用户内容、技术值和外部诊断的边界见下文精确例外规则。

## 语言基础与状态所有者

- `locales/registry.json` 是正式语言注册表，目前只注册 `zh-CN`。中文不随 Windows 语言自动改变。
- `backend/preferences.cjs` 只负责归一化和解析语言偏好；service 通过已抽离的 `settings-store.cjs`，将 `preferences.locale` 保存在原有 `settings.json` 中。它不属于编码 settings、预设或 RTX 签名。`null` 为后续“跟随系统”保留，目前仍解析为中文；不支持的值回退中文。
- `setLocale({ locale })` 先保存，成功后广播 `state.locale` 和 `state.preferences`。写入失败回滚内存，不广播未保存的选择。此入口不触发编码检测或任务重启，正式界面暂不提供选择器。
- `locales/runtime.mjs` 是不依赖文件、DOM 或进程的共享运行时。支持具名插值、按 `count` 选择 `one` / `other`、缺失或空译文回退中文、订阅以及 `Intl` 数字 / 日期 / 单位 / 文件大小格式化。调用方提供语言资源，新增语言时在统一入口注册。
- `src/LocaleRoot.tsx` 读取初始状态并订阅 IPC 更新；刷新已打开的 React 树，不通过 key 重新挂载。它同步 `html.lang`、标题，保留编辑状态。模块级选项保存 key，在渲染时获取文字；页面、管理窗口与原生入口均已接入，覆盖审阅与行为验收分别记录。

`node --test tests/locale.test.cjs tests/locale-encode.test.cjs` 验证回退、单复数、订阅、持久化 / 重启、保存失败和真实编码中的设置 / 命令稳定性。`node tests/desktop-locale.mjs` 单独构建测试样板，验证标题、静态选项、缺失 key、无障碍名称、未保存输入、键盘和窄窗口；正式应用的 preload / IPC 也在该测试中验证。测试语言只存在于 `tests/fixtures/i18n/`，测试构建输出至 `verification/`，不进入 `locales/`、`dist/` 或便携包。

## 共享显示与预设（B1）

`src/presentation.ts` 的状态、音频选项、淡入淡出选项与说明在渲染时取文案；调用方使用 `statusLabel()`、`audioLabels()`、`fadeOptions()`、`fadeHint()`。数字、时钟式时长与文件大小使用当前 locale 的 Intl 格式；大小仍按 1024 换算，单位采用 Intl 的写法（如中文 `kB`）。未知状态保留原始技术值，不能根据显示文字判断状态。编码器 ID、参数、音频选项值和淡入淡出秒数保持技术值。

`backend/definitions.cjs` 持有原有纯定义，`locales/builtin-presets.json` 将稳定内置 ID 关联到默认名称 key。`name` 与 `settings.presetName` 继续保存原名称；`nameKey` / `nameSource` 只用于显示投影，`settingsEdited` 与名称来源分开，`edited` 保留既有总修改标记。渲染使用 `presetLabel(p, peers)` / `engineLabel(e)`，不把译名送回 save / rename / apply 或命令构建。

新保存的内置覆盖带 `nameSource`：只保存参数时沿用原来源；显式改名标为 `user`，即使文字恰好等于当前中文默认名。旧覆盖没有改名意图，不能从 `edited` 或中文相等推断，因此其保存名称一律保守视为用户内容；它们不会自动获得译名。个人预设、旧历史、输出模板及用户文件名始终保留原文。改名输入框编辑的是保存名，不能预填译名后意外写回。

重名检查仍比较实际保存名、沿用原大小写规则，与界面 locale 无关。多个默认译名重合或碰到用户名称时，只在默认显示名旁补稳定 ID 区分；用户名称不变。按用户 2026-10-26 的新决定，程序新生成的保存名冲突后缀用固定英文 ` (Built-in)`、` (Modified)` / ` (Modified 2)`，独立标记继续本地化内置预设的显示。已有用户名称不重写，内置定义和指纹不变；添加译文或切换 locale 不触发预设更新冲突。

预设管理错误使用 `PRESET_*` code / params，公共请求层保留错误描述，App 在渲染时格式化错误与结构化通知。核心参数细项使用独立校验记录，默认名称及错误嵌套原因在显示时投影；确认 / 保存 / 导入导出窗口均使用当前语言。

插件配置为每项写入独立 `displayName`；原始 `name` 和 `settings.presetName` 不变，helper 继续消费这些原值。DLL 下拉框优先显示 `displayName`，旧配置缺失它时回退 `name`。共享显示函数位于 `locales/preset-names.mjs`，前端和配置生成共用，DLL 无需另一套名称映射。

验收入口：`tests/preset-locale.test.cjs` 的迁移前 SHA 快照对照全部 7 个默认预设的设置、指纹和命令；`tests/i18n.test.cjs`、`tests/desktop-locale.mjs` 验证共享显示、预设选择、用户名称、真实 IPC 错误及原位刷新；`mmd-plugin/tests/locale.mjs` 验证真实 DLL 下拉项、旧配置回退和保存 / 取消。

## 视频压制（B2）

视频设置、Alpha / RTX、队列操作、通用 / 单独设置、底部概览与兼容提示使用渲染时文案。`validateIssues()` 为核心问题列表；`validate()` 保留中文数组诊断投影。界面调用方读取 `issues` / `errorData`，由 `errorMessage()` 分别显示，不能解析中文消息来决定修复或重试。软件重试依据后端的系统错误码结果。

命令与任务阶段携带稳定 stage / params 和中文诊断回退，显示用 `stageMessage()`。新预览返回 `summaryData`，仅保存技术值与描述；`locales/video-summary.mjs` 在显示时取得编码器标签、单位及说明。原 `summary` 字符串保留作诊断投影，前端可调用 `summaryMessage(summaryData)` 原位刷新。`videoName()` 仅格式化 PNG 序列的程序注释，用户名称和输出模板原文不变。队列通知由 `notification()` 传描述给共享 actions，不提前固定为当前语言。

`tests/settings-issues.test.cjs` / `video-messages.test.cjs` 验证真实规则的消息契约、外部诊断和系统码；桌面语言样板覆盖本次组件与长文案，未提供正式日英翻译。遮罩格式等功能独立提交，不能把其行为变化归因于文案迁移。

用户在功能待办第六项改定 NVEncC 输出后，命令使用 `pipeFrom → NVEncC → pipeTo`，合并为编码与封装阶段，进度只读末段 FFmpeg 的 stdout。前段原始帧仍用 NUT；后段实测选用流式 Matroska，保留旧 MKV 的时间戳，避免 NVEncC 输出 NUT 时的首帧偏移。移除了临时 `.nvenc.mkv`、`video.nvenccHint` 和预览中的双倍磁盘说明；音频仍由末段 FFmpeg 处理。复制命令与 MMD helper 使用同一三段命令结构，任一成员失败停止整链。MMD 的 Job 仅用于显式终止，不设 `KILL_ON_JOB_CLOSE`；宿主消失时允许输入 EOF 自然收尾，保留可补完的隐藏视频。B6 已复验插件模拟器中的完整路径与强制中断补完，证据见实施记录；真实 MMD 工程另列验收。

遮罩格式字段为 `maskFormat`（lossless / gpu-lossy / x264-lossy），缺省无损且不改变内置指纹。选择只在分离或仅遮罩时显示，实际编码策略由 mask-settings 根据已试编码能力与尺寸决定。命令携带 `maskEncoding`，任务回退使用 `noteData` 的稳定码，显示层在渲染时翻译，不靠“lossless”字符串猜 GPU 使用情况。运行器以超时 / 取消标记和失败进程序号区分遮罩失败与下游失败；存储、超时、取消及下游编码 / 封装失败不会误触发有损遮罩回退。正常的新尝试清掉旧说明，自动 CPU 回退保留原因。桌面语言样板验证三选、刷新与长说明；实际剪辑软件导入由用户明确暂缓。

按功能待办第七项，视频音频码率只接受 64–512 kbps 的具体选项，默认 / 新个人预设为 320；不换算或兼容旧 0，命令没有 AAC 192k 或 Opus 自动码率兜底。两个旧“默认”文案键删除。两个 ProRes 内置预设的设置与指纹按用户授权更新，七个内置命令保持一致；这一差异不归因于语言迁移。音视频工具的“跟随源文件”0 含义不同，保持原行为。ArtCNN 提示改为“C4F32 慢约 30%–40%，画质差别不明显。”，超分补帧页删除两处重复小标题，原控件标签与分隔保留。

## 错误与迁移入口

后端 `appError(code, params)` 创建稳定错误码并保留中文诊断回退。共享数据契约见 `locales/messages.mjs` 及 [消息契约](消息契约.md)：错误保留 code / params / message，多条校验使用独立的 issues；阶段是 stage / params；历史摘要是 code / params / message。`src/i18n.ts` 提供错误、阶段和摘要的显示层格式化。旧的纯字符串记录原样显示，未知 code 回退原消息，不通过匹配中文猜测含义。

Electron 会丢弃被拒绝 Error 的自定义属性，因此 `desktop/actions.cjs` 将错误序列化为 `__mmdError: { code?, params, message, issues? }`。`preload.invokeResult` 按数据返回；迁移后的前端用 `src/ipc.ts` 的 `invoke()` 在渲染进程重建 Error，保留问题列表并按错误码显示。已有 `window.encoder.invoke()` 继续返回结果或拒绝消息；需要可靠读取结构化数据的消费方仍使用新入口。音频对齐窗口和自动对齐已使用该入口。

音频 worker 的失败 stderr 使用 `MMDENCODER_ERROR_V1 ` 加单行 JSON 和换行；成功的 preview stdout 始终是原始 PCM，align stdout 是原有结果 JSON。协议读取器分别保存完整记录和最多 4000 字符的原始诊断尾部，按 UTF-8 流解码；不依赖进程 data 事件正好对应一行。无结构化记录、损坏记录及未知码均有可读回退。对齐算法的“音频太短”和解码失败现在直接携带稳定 code / params，父进程不用从中文 detail 还原错误类型。

队列、核心校验、管理、历史和插件的生产 / 消费路径均已按 B1–B6 迁移；旧字符串历史保留原文，不从诊断反推结构。

验收入口：`tests/plugin-messages.test.cjs`、`tests/desktop-locale.mjs`、`mmd-plugin/tests/locale.mjs`。最后一项加载真实 DLL，验证主程序关闭时的测试语言、中文回退、长文案尺寸、当前选项测试、失败日志和取消 / 保存；它与真实 MMD 工程导出分别记录。原生测试会临时写实际 Known Folder 的配置，运行前关闭 MMD / MMDEncoder，结束自动恢复。

原生音频偏移按固定 30 fps 的整数帧保存，手动值与“起点为 1 时自动 +1”独立相加，不进入编码预设或语言偏好。主程序保存两项，plan 将它们冻结到导出快照；finish/recover 不读取后来修改的选择。AVI/WAV 按源采样率移动，WAV 原起点只计算一次，正偏移补前静音、负偏移扩读尾部，不足补静音并以视频时长为准。日志与消息保留实际/手动/自动来源。这是功能待办授权的行为，不能在翻译时更改。

## 管理、主题与字标

管理窗口、工具下载状态、更新进度和读取失败通知在显示时格式化，外部诊断仍可追溯。关于窗口删除了本版日志并按内容自适应高度；其他顶栏弹窗保持原高度约定。只有正式 registry 至少包含两种语言时才显示“界面语言 · Language”，仅向运行时注册测试包不会开放正式入口。

字段层级、注释、自动值占位和说明图标使用共享样式；主题 `system/light/dark` 由同一设置所有者持久化，与 locale 和 MMD 选择分离。图标与 `MMDEncoder` 字标属于品牌技术例外，Encoder 使用主题强调色；顶栏/关于已去掉标语。后续翻译不重新加入标语或把产品名拆成翻译资源。

运行 `node scripts/i18n-scan.mjs` 查看 `src/`、`backend/`、`desktop/`、`mmd-plugin/src/` 四层清单；加 `--json` 输出完整文字、文件、行列、字面量类型和分类。默认列出 JS / TS 含汉字的字符串、模板片段、JSX 文本，以及所有已审阅的精确例外；不计注释。`--all-literals` 额外列出 JS / TS 的纯 ASCII 字符串，供 C1 复核英文可见文字；资源 key、路径、协议、CSS 类名、SVG 和技术值也会在其中，不能把总数当作待翻译条数。两种范围均用语法树，ASCII 例外也逐项验证失效并保留可见。C++ 使用独立词法扫描，覆盖宽字符串、相邻字面量、转义和 raw string，同时保留 ASCII 字符串，避免漏掉原生控件与编码器名称。相邻 C++ 字面量分别列出，迁移时需要按完整句子合并。

分类值为 `interface`（界面）、`business`（业务消息）、`diagnostic`（诊断）和 `technical`（技术值）。自动建议不等于人工审校，也不自动排除任何条目。`scripts/i18n-exceptions.json` 按精确的文件与原文记录已审阅分类及理由，禁止整文件忽略；例外仍显示在清单中。缺少理由、重复或已失效的例外会使扫描失败。只有已审阅的诊断 / 技术值标为 `excluded`，不代表它们可以从清单消失。

清单不是翻译覆盖率：JS 的纯 ASCII 文字需要在逐页迁移时复核，用户输入、输出名称、技术 ID 与诊断也必须结合消费方判断。已集中到 `locales/` 的文案不计入扫描数量。运行 `node --test tests/i18n-scan.test.cjs` 验证清单工具。

`npm run i18n:check -- --json` 执行开发期 key 与参数检查：读取正式注册表，检查 JSON 重复 key、空消息、one/other、具名参数、正式包与完整测试包的一致性，以及 JS/TS 直接/条件引用、有限 key 表、消息描述生成器、内置预设名称映射与原生子表引用。测试包由 `tests/fixtures/i18n/pseudo.mjs` 从源表生成，不加入正式注册表或交付目录。检查只读项目源文件，不启动服务或写用户配置。

静态可确定的缺失 key / 参数、重复条目或源表不一致使命令失败。泛型转发、运行时拼接 key 和对象展开参数仍列在 `dynamic` / `deferredParameters`；`staticPassed` 仅表示静态部分通过，`reviewRequired` 非零时仍须结合生产者、消费者和对应测试复核，不能据此宣布 C1 或多语言准备完成。外部未知 code / key 的运行时回退由已有消息契约保留，不因检查器而改写产品行为。

C1 当前审阅快照：1357 个源 key（19 个单复数条目）、123 个插件子表 key；完整字面量清单 6809 次出现，默认清单中 342 次已审诊断/技术值。283 组精确 file/text 例外的理由由扫描器保留，不能用数量替代消费位置审阅。1502 条引用记录静态无缺漏；41 条动态路径和 2 条展开参数见[动态引用审阅](i18n-动态引用审阅.md)。这是对应源码的快照，改动 key 族或参数生产者后应重审。

## 准备完成后的正式语言入口

1. 先建立中/日/英术语表，产品名、codec、参数名、扩展名和固定技术命名保持；日语按 MMD 实际用语人工审校。此步骤不在准备阶段提前写译文。
2. 从中文完整源表建立 `ja.json` / `en.json`，逐 key 保留具名参数、one/other 和完整句子。正式注册 `locales/registry.json`，并在 `src/i18n.ts` 的集中资源入口加载对应 catalog；Electron main 按同一 registry 读取资源，再交给 service 的既有插件同步链路。
3. 运行 `npm run i18n:check -- --json`、两种扫描范围与 `node scripts/plugin-messages.mjs --check`。插件继续由同一源表生成有限子表与中文回退，不维护另一份手写译文。
4. 使用 `html.lang` 和原生 locale 选择相应字体，逐页完成真实中/日/英截图、键盘和无障碍检查，复用测试目录中的桌面语言入口；测试加长包只能证明机制和容纳能力。
5. 重跑计划要求的中文完整回归、日英冒烟和真实 MMD 短片；如形成候选包，核对真实解压目录、注册资源、中文启动与测试包排除。准备阶段的模拟器结果不能替代这些验收。README/GitHub 发行说明的翻译范围仍由用户另定。

新增或迁移一个模块时，同步迁移可见文字、无障碍名称和业务错误，添加语义 key 和稳定错误码；保留未知错误回退，再运行类型检查、相关测试和桌面验收。按模块推进，不按字符串批量替换；准备完成前不新增日英译文。

共享进程 runner 的原 `Error.code` / `systemCode` 是实际退出 / 系统信息，会影响取消和 GPU 遮罩重试，不用业务码覆盖。runner 自有的关闭、超时、无诊断退出及管道取消提示另附 `runnerErrorData`；`serializeError` 只将其 code / params 投影到显示与 IPC，原 Error 的退出码、stdout / stderr 和过程标志仍供后台原有控制流使用，未扩大 IPC 暴露范围。管道非空 stderr 仍优先原样显示，单进程原超时优先规则也保持；进程终止和参数与语言无关。

编码失败、文件详情、媒体元数据 / 批处理、检测通知和 RTX 等外层消息保留需要的 `params.error`，显示时再格式化内层。日志继续保留中文来源及实际技术输出；不能把历史日志反向匹配成 code。工具状态的正常 summary 与失败 errorData 都保留到渲染，重试 / 更换位置清旧原因；首次 notice 作为错误显示时显式保留 summary 语义，避免误用 error 命名空间。

预设管理弹窗、按钮 / 无障碍名称和完整确认句在渲染时取文案，通知保留 code / params。应用 / 覆盖通知只保存默认名称所需的稳定 ID / nameKey / 用户命名意图及同级名称快照，显示时重新投影，不把已翻译名称写回预设；用户输入、改名与固定技术默认名保持。预设参数错误保留 schema 原因或独立校验项，并保留原中文 fallback；未读个人预设 notice 保留其嵌套错误。Electron 原生预设导入 / 导出在打开时读取现有 service 语言，用注册表中已交付资源创建共享同步 translator；打开后的系统文件框保持其原生行为。读取失败 / 版本不支持用稳定错误码，JSON 内容、取消与保存规则不变。

Electron原生文件框在每次打开时取已保存locale，当前窗口自身文字保持原生快照；外部传入的自定标题与用户路径原样返回。预设/媒体输出默认英文文件名、格式扩展名与取消规则不随语言改变。main的拒绝条件保留，错误改带code/params；sandbox preload的invokeResult对未列入白名单的动作直接返回结构化失败且不调用IPC，legacy invoke仍拒绝。带码记录已经解包，其格式化结果中的原始诊断不再次移除Electron样式前缀；只有旧无结构包装继续清理前缀。复制命令的校验列表保留独立描述，显示时逐条格式化，失败不写剪贴板。

复制到PowerShell的自有提示也来自语言表。command-text在生成时接收窄text能力，引用翻译数据时转义PowerShell特殊字符，固定退出码占位才展开为进程表达式。main使用已有注册资源与本次已保存locale格式化，service只传locale字符串，queue不持有语言状态或窗口；完整命令图继续由原生成器拥有，不新增IPC命令图或编码偏好字段。日志和未提供显示格式化器的独立调用保留中文来源回退；选择复制时重新生成当前语言的脚本。中文脚本与迁移前一致，实际FFmpeg/NVEncC参数不随语言改变。
