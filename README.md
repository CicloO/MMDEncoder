# MMDEncoder

> [!NOTE]
> 这是作者的个人项目，不做宣传，也不承诺维护和支持。如有反馈，请单独告知作者。使用条款以 [MIT 许可证](LICENSE) 为准。

面向 MMD 创作者的 Windows 便携视频压制工具。批量压制渲染视频，支持透明通道、视频网站上传预设、NVIDIA 硬件编码与 RTX 视频增强。

项目地址：<https://github.com/CicloO/MMDEncoder>

## 功能

- **批量压制**：H.264 / HEVC / AV1 / VP9 / ProRes，MP4 / MKV / MOV / WebM 容器；软件编码、NVENC、NVEncC，以及 Intel QSV / AMD AMF 硬件编码。
- **内置预设**：默认 4K、默认 1080p 各有硬件（NVENC）和软件（x264）两个版本，按长边缩放、自动识别横竖屏，软件版本在本机支持 NVENC 时默认隐藏；另有两个透明素材预设（ProRes 4444、H.264 + 黑白遮罩）；内置预设也能改名、更新、隐藏、删除和恢复；可以保存、导入、导出个人预设，拖动排序。
- **检查更新**：启动时自动查询 GitHub Releases，有新版本时提示。
- **透明通道**：保留 Alpha（ProRes 4444、VP9、NVEncC HEVC），或转为 RGB 并另外输出灰度遮罩，也可以把透明区域合成到绿幕（#00FF00）。
- **分辨率与帧率**：自定义输出尺寸（默认保持各视频自身的宽高比），以及帧率转换。
- **RTX 增强**：RTX Video Super Resolution 放大（1–4 倍），RTX 插帧（2–8 倍）。
- **音视频提取与合并**：单独导出音频（WAV / FLAC / AAC / MP3 / Opus），去除音轨，替换音轨，输出 MP4 或 MKV。
- **安全输出**：默认输出到源目录的 `Encoded` 子目录，不覆盖源文件和已有输出；硬件编码失败时可以改用软件编码重试；可复制实际执行的命令。

## 系统要求

- Windows 10 / 11 x64
- 首次使用需要联网下载编码工具，之后可以离线使用
- 硬件编码需要相应显卡；RTX 插帧需要 Ada（RTX 40）或 Blackwell（RTX 50）显卡、NVIDIA VFX 运行库和模型

## 安装与使用

1. 从 [Releases](https://github.com/CicloO/MMDEncoder/releases) 下载 `MMDEncoder-<版本>-win-x64.zip`，解压到任意目录。
2. 运行 `MMDEncoder.exe`。
3. 第一次使用时，在“编码引擎”中点击“下载并安装最新工具”。
4. 添加视频，选择预设，检查预计结果后开始压制。

软件包本身不包含 FFmpeg、ffprobe 和 NVEncC，它们在第 3 步下载：

- FFmpeg / ffprobe：[Gyan full builds](https://www.gyan.dev/ffmpeg/builds/)
- NVEncC：[rigaya/NVEnc Releases](https://github.com/rigaya/NVEnc/releases)

工具默认安装在 `%LOCALAPPDATA%\MMDEncoder\tools`，不需要管理员权限；也可以在“编码引擎”里点“更改位置”换到别的文件夹，已安装的工具会一起移过去（选择已装有本软件工具的文件夹则直接使用），“恢复默认位置”可改回。选择的位置记在软件目录的 `data` 里。之后可以离线使用，需要时在“编码引擎”中手动检查更新。更新时会先校验并验证新版本，失败则保留旧版本；正在压制时不能更新。

### 软件更新

软件启动时会查询一次本项目的 [GitHub Releases](https://github.com/CicloO/MMDEncoder/releases)，有新版本时给出提示；也可以在右上角“设置与引擎”里点“检查更新”。

有新版本时点“下载并更新”：软件下载新的压缩包，先核对发行页上的 SHA-256，校验通过后解压到软件目录下的 `.update` 文件夹；再点“重启并完成更新”，软件关闭，由新版本自带的更新程序替换程序文件并重新打开。`data` 文件夹（设置、个人预设、日志）保留不动；替换失败会自动还原旧版本，过程记在 `data\logs\update.log`。更新不使用 PowerShell，也不需要管理员权限，但软件目录要可写；正在压制时不能更新。

更新会带来新版的内置预设：某个内置预设在新版里有改动时直接换成新版（你对这一项做的改名或修改不再保留），个人预设始终保留。

也可以点“打开下载页”手动下载解压，再把旧版的 `data` 复制到新版目录。从 1.2.4 及更早版本升级到 1.3.0 需要手动下载这一次，之后的版本可以自动更新。

## 使用说明

### 视频压制

添加视频，选择个人预设或内置预设，检查预计结果后开始压制。输出默认位于源目录的 `Encoded` 子目录。

队列可以拖动排序，处理中拖动也会按新顺序继续。已完成或已取消的视频，可以点条目右侧 × 左边的刷新按钮“重新导出”：它会回到待压制状态，下次开始压制时按当前设置导出；已有的输出文件不会被覆盖，新文件自动编号，如 `xxx (2).mp4`。

设置不兼容时，底部提示条会给出可以一键应用的修正方案，只调整相关设置，不改动帧率、输出目录等其他选择。

### 透明通道

“透明通道”页的“透明通道处理”有四种选择：

- **移除 Alpha**：透明区域按原像素颜色输出。
- **保留 Alpha**：输出带透明通道的视频，只能用下面三种格式。
- **分离 Alpha**：彩色视频不带 Alpha，另外导出一个同尺寸、同帧率的黑白遮罩（`_alpha` 后缀，无损）。对编码器和封装没有要求。
- **合成到绿幕**：把透明区域填成 #00FF00，方便后期抠像。

可以保留 Alpha 的格式：

- ProRes 4444（MOV / MKV，4:4:4）
- VP9（WebM / MKV，8-bit，4:2:0）
- NVEncC HEVC（MP4 / MOV / MKV，8-bit，4:2:0，需本机试编码通过）

这三种格式都能把 Alpha 写进文件，但能不能读出来取决于用的软件：

| 格式        | Alpha 存放方式                             | 能读到透明                                                               | 读不到透明                                                                  |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| ProRes 4444 | 每一帧的第四个通道，剪辑行业标准           | Windows 和 Mac 上的 After Effects、Premiere、DaVinci Resolve、Final Cut  | 基本没有                                                                    |
| VP9（WebM） | 另存的一路附加数据，主要为网页透明视频设计 | Chrome、Firefox、OBS 浏览器源                                            | After Effects、Premiere 不能直接导入 WebM                                   |
| HEVC Alpha  | 苹果定义的规格：彩色是主层，Alpha 是辅助层 | macOS 系统解码器、Safari，以及 Mac 版 Final Cut、After Effects、Premiere | Windows 版 After Effects、Premiere 和系统播放器（只解码主层，看起来不透明） |

在 Windows 上用 After Effects 等软件后期，请选 ProRes 4444（内置预设“保留 Alpha · ProRes 4444”）或“分离 Alpha”。需要与 MMD2FFMPEG 插件相同的 HEVC Alpha（适合 Mac 软件）时，把编码器选为 HEVC · NVEncC、透明通道选“保留 Alpha”即可。保留 Alpha 失败时不会改用软件编码而悄悄丢掉透明度。

### RTX 增强

只能配合 NVEncC 使用，选好 VSR / VFG 后要先点“验证本机 RTX 设置”，通过后才能压制。

- **VSR 超分辨率**：放大 1–4 倍，或在原尺寸下去噪、去模糊、补细节。档位怎么选见下方 [RTX 视频增强（VSR）怎么选](#rtx-视频增强vsr怎么选)。
- **VFG 插帧**：2–8 倍，在源帧率基础上乘倍率。需要 Windows、Ada / Blackwell 显卡、NVEncC 9.36+、NVIDIA VFX 运行库和模型。
- RTX 增强暂时不能和保留 Alpha、独立遮罩一起使用。

### 音视频提取与合并

- 只导出音频（WAV / FLAC / AAC / MP3 / Opus，或直接复制原音轨）。AAC / MP3 / Opus 可选码率，默认跟随源文件码率；源文件是无损音频（WAV、FLAC 等）时用 320 kbps。
- 去除视频的音轨。
- 用独立音频替换原音轨。默认按较短的一条流结束，可以取消这个选项。

和视频压制页一样是批量队列：把多个文件拖进窗口或点“添加文件”，开始处理后逐个导出，每个文件显示自己的状态。合并时，拖入的音频会配给选中的视频（或第一个还没有音频的视频），也可以点条目上的音符按钮单独选择。

输出文件名自动生成，位置可选：**与源文件同目录**（默认）、源目录下的 `Encoded` 子文件夹，或自定义文件夹。已有文件不覆盖、自动编号。已完成、已取消或失败的条目可以点刷新按钮“重新导出”，也可以“清除已完成”。

视频取第一条视频流直接复制、不重新压制，输出 MP4（默认）或 MKV；MP4 放不下的编码（如 MMD 直接输出的 AVI 原始视频、WAV 音频）会自动改用 MKV，并在日志中注明。音频取第一条音频流，源文件保持不变。选中文件后可以点“文件详情”对比转换前后的参数。

### 文件详情

直接用 ffprobe 读取源文件和实际输出文件的参数，转换前、后左右并排对比。输出还没生成时显示“尚未生成文件”，不会推测转换后的参数。

## 内置预设

默认 4K / 1080p 预设适合上传 B站、抖音 / TikTok、YouTube 等视频网站：H.264 8-bit 4:2:0 BT.709，AAC 320 kbps。分辨率按**长边**缩放，自动识别横竖屏：横屏视频长边是宽，竖屏视频长边是高，另一边按原比例计算。1080p 渲染放大到 4K，可以进入网站的高码率档位。

- **· 硬件**：NVIDIA NVENC（p4，恒定质量 CQ 29），需要 NVIDIA 显卡，几乎不占 CPU。实测 p4 与 p7 画质相同、速度约快一倍多。
- **· 软件**：x264（medium，恒定质量 CRF 21，码率与硬件版相近），任何电脑都能用，速度取决于 CPU。本机支持 H.264 NVENC 时默认隐藏，可在“预设管理”里点眼睛图标显示。

| 预设            | 长边     | 例：1920×1080 → | 例：1080×1920 → |
| --------------- | -------- | --------------- | --------------- |
| 默认 4K         | 3840     | 3840×2160       | 2160×3840       |
| 默认 1080p      | 1920     | 1920×1080       | 1080×1920       |
| 两个 Alpha 预设 | 源分辨率 | 1920×1080       | 1080×1920       |

透明素材预设，分辨率都跟随源视频：

- **保留 Alpha · ProRes 4444**：ProRes 4444（4:4:4，带 Alpha，量化 8），MOV，PCM 音频。After Effects、Premiere 可以直接读到透明通道，最省事。只能 CPU 编码，但速度快于实时；4K 每秒约 16 MB。
- **分离 Alpha · H.264 MP4**：彩色视频用默认 4K / 1080p 硬件预设的参数（H.264 NVENC、CQ 29、AAC 320 kbps），MP4，另外输出一个 `_alpha.mp4` 黑白遮罩（无损 H.264，实测比有损压缩还小）。在 AE 里把遮罩放在彩色视频上方，彩色层的轨道遮罩选“亮度遮罩”。文件最小。

ProRes 的“画质 · 量化”可以在“画质”页调整：1–64，数值越小质量越高、文件越大；0 为编码器默认（约为量化 8 的 4 倍大小）。

想自己设定长边，可以在“画质”页把输出分辨率选为“按长边缩放 · 自动识别横竖屏”。

> 各网站没有公开完整的上传规格（YouTube 除外），这些参数来自社区经验和本机实测，尚未经过全面的实际上传验证。参数依据和取舍见 [docs/平台上传预设.md](docs/平台上传预设.md)，硬件 / 软件编码的速度与画质实测见 [docs/编码器实测对比.md](docs/编码器实测对比.md)。

## RTX 视频增强（VSR）怎么选

VSR 在“RTX 增强”页设置，只能配合 NVEncC 使用，开始前要先点“验证本机 RTX 设置”。“NVIDIA QualityLevel”每 4 档为一组，组内从低到高是 Low / Medium / High / Ultra，数字越大效果越好，也越占显卡：

| 档位    | 作用                   | 适合的素材                           |
| ------- | ---------------------- | ------------------------------------ |
| 0       | 双三次放大（对照基线） | 只用来对比效果                       |
| **1–4** | VSR 放大，4 最好       | **干净的渲染画面放大，MMD 属于这类** |
| 8–11    | 去噪，保持原尺寸       | 有噪点的实拍、低光素材               |
| 12–15   | 去模糊，保持原尺寸     | 被压缩糊掉的素材                     |
| 16–19   | 补细节，保持原尺寸     | 原尺寸输出，只想让画面更锐           |
| 21 / 23 | 修复直播流压缩伪影     | 低码率直播录像                       |

MMD 渲染输出本身很干净，建议：

- **放大（如 1080p → 4K 上传）**：选 **4**，倍率 2。强度先用 1；如果线条边缘出现白边或过锐，降到 0.5–0.7。
- **不放大**：可以试 16–19，但要先和原片对比，看描边是否过锐。
- **去噪、去模糊、直播档**：MMD 一般用不上，去模糊还可能让描边过锐。

VSR 与普通的自定义分辨率不能同时使用。用默认 4K / 1080p 预设时，如果想改用 VSR 放大，请把输出分辨率改回“源分辨率”，再把 VSR 倍率设为 2。

## 从源码构建

需要 Node.js 22+、pnpm 和 Windows x64。

```powershell
pnpm install
pnpm build      # 类型检查并构建界面
pnpm start      # 启动开发版
pnpm package    # 打包便携版
node scripts/zip-portable.mjs
```

开发版从本机安装目录读取编码工具。可以用环境变量 `MMD_ENCODER_TOOLS_ROOT` 指向其他工具目录。

### 测试

```powershell
$env:MMD_TEST_TOOLS_ROOT = "<工具目录>"
node --test tests/*.test.cjs   # 单元测试和真实引擎测试
node tests/desktop.mjs         # 桌面流程测试
node tests/desktop-tools.mjs   # 工具安装流程测试
node tests/rtx-live.cjs        # RTX 实机测试（需要 NVIDIA 显卡）
```
