# MMDEncoder

面向 MMD 创作者的 Windows 便携视频压制工具。批量压制渲染视频，支持透明通道、视频网站上传预设、NVIDIA 硬件编码与 RTX 视频增强。

项目地址：<https://github.com/CicloO/MMDEncoder>

## 功能

- **批量压制**：H.264 / HEVC / AV1 / VP9 / ProRes，MP4 / MKV / MOV / WebM 容器；软件编码、NVENC、NVEncC，以及 Intel QSV / AMD AMF 硬件编码。
- **内置预设**：默认 4K、默认 1080p 各有硬件（NVENC）和软件（x264）两个版本，按长边缩放、自动识别横竖屏；另有两个透明素材预设（ProRes 4444、H.264 + 黑白遮罩）和一个剪辑素材预设（ProRes 422 HQ）；内置预设也能改名、更新、隐藏、删除和恢复；可以保存、导入、导出个人预设，拖动排序。
- **PNG 图片序列**：把 `name_0001.png` 这样连续编号的 PNG 当作视频压制，支持透明通道；帧率自己选（默认 30 FPS）。
- **检查更新**：启动时自动查询 GitHub Releases，有新版本时提示。
- **透明通道**：保留 Alpha（ProRes 4444、VP9、NVEncC HEVC），或转为 RGB 并另外输出灰度遮罩，也可以把透明区域合成到绿幕（#00FF00）。
- **分辨率与帧率**：自定义输出尺寸（默认保持各视频自身的宽高比），以及帧率转换。
- **RTX 增强**：RTX Video Super Resolution 放大（1–4 倍），RTX 插帧（2–8 倍）。
- **无损剪辑**：把视频分段裁切、首尾拼接，视频逐包复制、画质不变；切点吸附到可以无损切开的位置，支持帧号、时间和 MMD 帧号定位。
- **MMD 导出插件**：在 MMD 的“AVI 输出”里选择“MMDEncoder”，直接按预设导出带音频的成片，不生成巨大的 AVI；不从第 0 帧导出时自动从工程 WAV 截取音频。
- **音视频提取与合并**：单独导出音频（WAV / FLAC / AAC / MP3 / Opus），去除音轨，替换音轨，输出 MP4 或 MKV；WAV / FLAC 可选 Hi-Res（24-bit，低于 48 kHz 时升到 2 倍采样率；视频压制页的 FLAC / PCM 同样可选）。
- **安全输出**：默认输出到源目录的 `Encoded` 子目录，不覆盖源文件和已有输出；硬件编码失败时可以改用软件编码重试；可复制实际执行的命令。

## 系统要求

- Windows 10 / 11 x64
- 首次使用需要联网下载编码工具，之后可以离线使用
- 硬件编码需要相应显卡；RTX 插帧需要 Ada（RTX 40）或 Blackwell（RTX 50）显卡、NVIDIA VFX 运行库和模型

## 安装与使用

1. 从 [Releases](https://github.com/CicloO/MMDEncoder/releases) 下载 `MMDEncoder-<版本>-win-x64.zip`，解压到任意目录。
2. 运行 `MMDEncoder.exe`。
3. 第一次使用时，在“编码引擎”中点击“下载并安装最新工具”。
4. 添加视频，选择预设，检查预计结果后开始压制。

软件包本身不包含 FFmpeg、ffprobe 和 NVEncC，它们在第 3 步下载：

- FFmpeg / ffprobe：[Gyan full builds](https://www.gyan.dev/ffmpeg/builds/)
- NVEncC：[rigaya/NVEnc Releases](https://github.com/rigaya/NVEnc/releases)

工具默认安装在 `%LOCALAPPDATA%\MMDEncoder\tools`，不需要管理员权限；也可以在“编码引擎”里点“更改位置”换到别的文件夹，已安装的工具会一起移过去（选择已装有本软件工具的文件夹则直接使用），“恢复默认位置”可改回。选择的位置记在软件目录的 `data` 里。之后可以离线使用，需要时在“编码引擎”中手动检查更新。更新时会先校验并验证新版本，失败则保留旧版本；正在压制时不能更新。

### 软件更新

软件启动时会查询一次本项目的 [GitHub Releases](https://github.com/CicloO/MMDEncoder/releases)，有新版本时给出提示；也可以在右上角“设置与引擎”里点“检查更新”。

有新版本时点“下载并更新”：软件下载新的压缩包，先核对发行页上的 SHA-256，校验通过后解压到软件目录下的 `.update` 文件夹；再点“重启并完成更新”，软件关闭，由新版本自带的更新程序替换程序文件并重新打开。`data` 文件夹（设置、个人预设、日志）保留不动；替换失败会自动还原旧版本，过程记在 `data\logs\update.log`。更新不使用 PowerShell，也不需要管理员权限，但软件目录要可写；正在压制时不能更新。

更新会带来新版的内置预设：某个内置预设在新版里有改动时会换成新版。如果你之前改过这个预设（改名或修改参数），打开软件时会弹窗询问：选“用新版覆盖”丢弃你的修改，选“保留我的版本”把它另存为个人预设（名称后加“（我的修改）”）；暂时关掉窗口的话，下次打开还会再问。个人预设始终保留。

也可以点“打开下载页”手动下载解压，再把旧版的 `data` 复制到新版目录。从 1.2.4 及更早版本升级到 1.3.0 需要手动下载这一次，之后的版本可以自动更新。

## 使用说明

### 视频压制

添加视频，选择个人预设或内置预设，检查预计结果后开始压制。输出默认位于源目录的 `Encoded` 子目录。

队列可以拖动排序，处理中拖动也会按新顺序继续。已完成或已取消的视频，可以点条目右侧 × 左边的刷新按钮“重新导出”：它会回到待压制状态，下次开始压制时按当前设置导出；已有的输出文件不会被覆盖，新文件自动编号，如 `xxx (2).mp4`。

**PNG 图片序列**：把装有序列的文件夹拖进队列，或在“添加视频”里选其中任意一张 PNG（多选同一序列的几张也只加一次）。文件名末尾要有连续编号，如 `dance_0001.png`、`dance_0002.png`…（补零或不补零都可以）；缺了某一帧时会提示缺第几帧，不会悄悄截短。图片本身没有帧率，在“当前素材”里选“序列帧率”（23.976–120，默认 30），时长随之改变。带透明的 PNG 可以直接保留 Alpha 或分离遮罩；输出以编号前的名字命名（`dance.mp4`），没有音轨。

**剪辑友好**：“高级”分页的选项（默认关闭）。GOP 间隔为自动时改为每秒一个关键帧，成片之后可以按约 1 秒的间隔无损裁切；同画质下文件约大 2%~5%（软件 H.264 多一些）。软件编码的 HEVC 始终使用闭合 GOP。

**Hi-Res 音频**：“音频”分页选 FLAC 或 PCM 时可以勾选，规则与音视频页相同（24-bit，源低于 48 kHz 时升到 2 倍采样率），按每个视频自己的音轨计算；PCM 输出 24-bit，只能用 MOV 或 MKV，勾选时 MP4 会自动改为 MKV。这个选项会存进预设，用于 MMD 导出时成片也是 Hi-Res 音轨。

设置不兼容时，底部提示条会给出可以一键应用的修正方案，只调整相关设置，不改动帧率、输出目录等其他选择。

### 透明通道

“透明通道”页的“透明通道处理”有四种选择：

- **移除 Alpha**：透明区域按原像素颜色输出。
- **保留 Alpha**：输出带透明通道的视频，只能用下面三种格式。
- **分离 Alpha**：彩色视频不带 Alpha，另外导出一个同尺寸、同帧率的黑白遮罩（`_alpha` 后缀，无损）。对编码器和封装没有要求。
- **分离 Alpha · 仅黑白遮罩**：只导出黑白遮罩（`_alpha` 后缀，无损，不含音频），不导出彩色视频。WebM 用 VP9，其他格式用 H.264，与画质页选的编码器无关。适合已经有彩色成片、只差一份遮罩的情况。
- **合成到绿幕**：把透明区域填成 #00FF00，方便后期抠像。

可以保留 Alpha 的格式：

- ProRes 4444（MOV / MKV，4:4:4）
- VP9（WebM / MKV，8-bit，4:2:0）
- NVEncC HEVC（MP4 / MOV / MKV，8-bit，4:2:0，需本机试编码通过）

这三种格式都能把 Alpha 写进文件，但能不能读出来取决于用的软件：

| 格式        | Alpha 存放方式                             | 能读到透明                                                               | 读不到透明                                                                  |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| ProRes 4444 | 每一帧的第四个通道，剪辑行业标准           | Windows 和 Mac 上的 After Effects、Premiere、DaVinci Resolve、Final Cut  | 基本没有                                                                    |
| VP9（WebM） | 另存的一路附加数据，主要为网页透明视频设计 | Chrome、Firefox、OBS 浏览器源                                            | After Effects、Premiere 不能直接导入 WebM                                   |
| HEVC Alpha  | 苹果定义的规格：彩色是主层，Alpha 是辅助层 | macOS 系统解码器、Safari，以及 Mac 版 Final Cut、After Effects、Premiere | Windows 版 After Effects、Premiere 和系统播放器（只解码主层，看起来不透明） |

在 Windows 上用 After Effects 等软件后期，请选 ProRes 4444（内置预设“保留 Alpha · ProRes 4444”）或“分离 Alpha”。需要与 MMD2FFMPEG 插件相同的 HEVC Alpha（适合 Mac 软件）时，把编码器选为 HEVC · NVEncC、透明通道选“保留 Alpha”即可。保留 Alpha 失败时不会改用软件编码而悄悄丢掉透明度。

### RTX 增强

只能配合 NVEncC 使用，选好 VSR / VFG 后要先点“验证本机 RTX 设置”，通过后才能压制。

- **VSR 超分辨率**：放大 1–4 倍，或在原尺寸下去噪、去模糊、补细节。档位怎么选见下方 [RTX 视频增强（VSR）怎么选](#rtx-视频增强vsr怎么选)。
- **VFG 插帧**：2–8 倍，在源帧率基础上乘倍率。需要 Windows、Ada / Blackwell 显卡、NVEncC 9.36+、NVIDIA VFX 运行库和模型。
- RTX 增强暂时不能和保留 Alpha、独立遮罩一起使用。

### 音视频提取与合并

- 只导出音频（WAV / FLAC / AAC / MP3 / Opus，或直接复制原音轨）。AAC / MP3 / Opus 可选码率，默认跟随源文件码率；源文件是无损音频（WAV、FLAC 等）时用 320 kbps。
- 去除视频的音轨。
- 用独立音频替换原音轨。默认按较短的一条流结束，可以取消这个选项。
- **Hi-Res 音频**（输出 WAV / FLAC 时可选）：统一输出 24-bit；源低于 48 kHz 时升到 2 倍采样率（44.1 → 88.2 kHz、32 → 64 kHz），48 kHz 及以上保持原采样率。32-bit 和浮点源加抖动降为 24-bit；源已经是同格式的 24-bit 时直接复制，不重新编码。合并时按替换音频本身的参数计算，并输出 MKV。当前安装的 FFmpeg 带 soxr 时用 soxr 重采样，否则用 FFmpeg 自带的高质量重采样。勾选后会显示转换结果，例如“44.1 kHz / 16-bit → 88.2 kHz / 24-bit”。升采样不会让音质变好，只是满足平台对 Hi-Res 的判定（平台规则来自社区说法，尚未实际上传验证）。

和视频压制页一样是批量队列：把多个文件拖进窗口或点“添加文件”，开始处理后逐个导出，每个文件显示自己的状态。合并时，拖入的音频会配给选中的视频（或第一个还没有音频的视频），也可以点条目上的音符按钮单独选择。

输出文件名自动生成，位置可选：**与源文件同目录**（默认）、源目录下的 `Encoded` 子文件夹，或自定义文件夹。已有文件不覆盖、自动编号。已完成、已取消或失败的条目可以点刷新按钮“重新导出”，也可以“清除已完成”。

视频取第一条视频流直接复制、不重新压制，输出 MP4（默认）或 MKV；MP4 放不下的编码（如 MMD 直接输出的 AVI 原始视频、WAV 音频）会自动改用 MKV，并在日志中注明。音频取第一条音频流，源文件保持不变。选中文件后可以点“文件详情”对比转换前后的参数。

### 无损剪辑

把一个或多个视频按顺序切段、首尾相接，视频逐包复制，不重新压制，画质与原片完全相同。

1. 点“无损剪辑”，拖入视频或点“添加视频”。每个文件读取一次关键帧（通常不到 1 秒）。同一个文件可以点复制按钮“再切一段”。
2. 选中片段，拖动滑块或用 ←/→ 逐帧查看，Shift+←/→ 跳到上一个 / 下一个可切位置；按 I / O（或“设为入点 / 出点”）设定范围，也可以直接输入帧号或时间（如 `1234`、`00:00:41.133`）。勾选“按 MMD 帧号输入”后，数字按 MMD 的 30 FPS 时间轴换算（60 FPS 成片里 MMD 第 400 帧就是第 800 帧）。出点那一帧不包含在内，`end` 表示到结尾。
3. 选择音频方式和输出位置，点“导出”。文件名是第一个片段的名字加“_剪辑”，已有文件不覆盖。

- **切点**：无损只能从解码器可以独立开始的位置切开。H.264 / HEVC 只能在 IDR 帧切开（MMDEncoder 预设开启“剪辑友好”后约每秒一个）；ProRes、UtVideo 每一帧都可以；FFV1 在关键帧处可以。输入的位置会吸附到最近的可切位置，界面同时显示输入值和实际值。开放 GOP 的关键帧（x264 open-gop、x265 默认）从中间开始会花屏，不能作为切点；VP9、AV1 等暂不支持。
- **MMD 帧号**：勾选“按 MMD 帧号输入”后，按 MMD 时间轴（30 FPS）换算，并从片段的起始 MMD 帧算起。MMD 导出的文件名带 `_0400-0600f` 这样的帧范围（默认开启，可在“MMD 导出”或 MMD 的“詳細設定”里关闭），起始帧也写在文件信息里，加入剪辑页时自动识别；其他文件可以手动填写“视频第 0 帧 = MMD 第几帧”。
- **智能剪切**（默认关闭）：按输入的帧精确切开。只有切点到最近关键帧之间的几帧用原片的编码参数重新编码（这几帧有损），其余直接复制；重新编码后核对编码参数集与原片完全一致，否则不导出。需要 MMDEncoder 1.5.0 起导出的 H.264 / HEVC（文件里记录了编码参数），本机编码器须与导出时相同；ProRes、UtVideo 本来就能逐帧切，不需要。
- **音频**：默认保留原音频，每段按采样点精确截取后重新编码（AAC / FLAC / PCM），接缝不做淡入淡出；也可以替换为外部音频（正偏移表示从音频的这个位置开始用，负偏移表示视频开头先空这么久）或不要音频。原音频不够长的地方补静音，总长度始终与视频一致。
- **拼接不同文件**：要求编码、分辨率、像素格式、帧率、色彩参数和编码参数集完全一致（例如同一预设导出的视频），否则会列出不同之处并且不导出。
- **可变帧率（VFR）**的视频不能无损剪辑，请先在“视频压制”里转成固定帧率。
- 剪辑导出时不能同时压制、检测编码器、管理工具或更新软件；关闭软件会停止导出并清理临时文件。
- 预览只显示主画面，不显示透明通道；ProRes 4444 的 Alpha 会原样保留在成片里。

### MMD 导出插件

把 MMDEncoder 的一个预设当作 MMD 的视频编码器使用：

1. 点右上角的“MMD 导出”，在“插件”一节点“安装到 MMD”。插件只为当前 Windows 用户注册，不需要管理员；MMD 已打开时，重启 MMD 后生效。
2. 选择“导出预设”，可以点“测试编码”确认本机能用这个预设编码。导出预设、“分辨率和帧率跟随 MMD”、Alpha 遮罩和音频淡入淡出也可以在 MMD 里改：在“AVI 输出”选中“MMDEncoder”后点“詳細設定”（窗口左下角的“打开 MMDEncoder”可以直接切到本软件），两边的选择会同步，以最后保存的为准；在 MMD 里保存的选择会立即反映到 MMDEncoder。
3. 在 MMD 里选 文件 → AVI 输出，视频编码选“MMDEncoder”，照常输出。

成片保存在 MMD 选的 AVI 路径旁边、同名（例如 `scene.mp4`），已有文件不覆盖、自动编号（渲染期间才出现的同名文件也不会被覆盖）；每次导出都按开始时的预设和选项完成，渲染中途改预设不影响这一次；渲染结束后在后台合成音频，并删除 MMD 生成的占位 AVI（插件只删除自己写的占位文件）。

- **音频**：从第 0 帧开始导出时使用 AVI 里的音频；从其他帧开始时 MMD 不写音频，插件会读取工程（.pmm）里的 WAV，按“起始帧 ÷ 30”秒的位置精确截取对应长度。工程需要先保存过，WAV 文件要还在原位置。
- **分辨率和帧率跟随 MMD**（默认开启）：使用 MMD“AVI 输出”里设定的尺寸和帧率，忽略预设里的分辨率与帧率；编码器、画质和音频仍按预设。关闭后按预设缩放和转换帧率。
- **Alpha 遮罩**（不导出 / 同时导出遮罩 / 仅导出遮罩）：这里的选择优先于预设自带的遮罩设置；选中自带遮罩的预设时会自动切到对应选项，之后仍可修改。“同时导出遮罩”在成片之外再导出同名 `_alpha` 黑白遮罩（无损，白色不透明、黑色透明），任何预设都可以用。MMD 送来的画面只读一次，由同一个 FFmpeg 分成两路编码；实测 4K 竖屏下编码速度约降低 40%，但通常仍快于 MMD 渲染，总导出时间基本不变（数据见 [docs/编码器实测对比.md](docs/编码器实测对比.md) 第 6 节）。遮罩总会保留，即使整段全白（画面没有透明区域）也一样，要不要用由你判断。“仅导出遮罩”只输出 `_alpha` 遮罩（没有彩色画面和音频），比完整导出快。
- **音频淡入淡出**：可选 0.5 / 1 / 2 秒，让从歌曲中间截取的片段首尾不会突然开始或结束。
- 暂不支持 NVEncC（含 RTX 超分 / 补帧）预设。
- **意外中断**：在 MMD 里取消导出时，已渲染的部分照常保存成片，并合成对应长度的音频。MMD 崩溃或被关闭时，已导出的画面仍在临时文件里；下次打开 MMDEncoder 会提示，在“MMD 导出”的“中断的导出”里可以补完（按开始时的设置合成音频、改回正式文件名）或删除。
- 导出失败时 MMD 会弹出提示；日志在 `%LOCALAPPDATA%\MMDEncoder\mmd-plugin\logs`，也可以在“MMD 导出”里点“打开导出日志”。点“打开最新导出”可以直接在资源管理器里找到最近一次导出的成片。

安装说明：

- **不需要找 MMD 目录**：插件不会放进 MMD 文件夹，而是复制到 `%LOCALAPPDATA%\MMDEncoder\mmd-plugin\bin` 并注册为 Windows 视频编码器（和 UtVideo 等编码器一样）。MMD 的编码列表来自系统，所以无论 MMD 装在哪里、有几份，都能看到“MMDEncoder”，MMD 文件夹里的文件也不会被改动。
- **只支持 64 位 MMD**（9.x 64 位版）。32 位的旧版 MMD 看不到这个插件。
- **按 Windows 用户注册**：哪个用户安装，哪个用户的 MMD 才能用；同一台电脑的其他 Windows 账户需要各自安装一次。
- **移动了 MMDEncoder 文件夹后**，插件仍会去旧位置调用 MMDEncoder，导出会失败并提示。重新打开一次 MMDEncoder 即可自动更新为新位置，不需要重装插件。
- 少数安全软件可能拦截插件注册；如果点“安装到 MMD”后仍显示未安装，请在安全软件里放行后重试。
- 卸载：在“MMD 导出”里点“卸载”。

### 文件详情

直接用 ffprobe 读取源文件和实际输出文件的参数，转换前、后左右并排对比。输出还没生成时显示“尚未生成文件”，不会推测转换后的参数。

## 内置预设

默认 4K / 1080p 预设适合上传 B站、抖音 / TikTok、YouTube 等视频网站：H.264 8-bit 4:2:0 BT.709，AAC 320 kbps。分辨率按**长边**缩放，自动识别横竖屏：横屏视频长边是宽，竖屏视频长边是高，另一边按原比例计算。1080p 渲染放大到 4K，可以进入网站的高码率档位。

- **· 硬件**：NVIDIA NVENC（p4，恒定质量 CQ 29），需要 NVIDIA 显卡，几乎不占 CPU。实测 p4 与 p7 画质相同、速度约快一倍多。
- **· 软件**：x264（medium，恒定质量 CRF 21，码率与硬件版相近），任何电脑都能用，速度取决于 CPU。不需要的预设可以在“预设管理”里点眼睛图标隐藏。

| 预设                     | 长边     | 例：1920×1080 → | 例：1080×1920 → |
| ------------------------ | -------- | --------------- | --------------- |
| 默认 4K                  | 3840     | 3840×2160       | 2160×3840       |
| 默认 1080p               | 1920     | 1920×1080       | 1080×1920       |
| Alpha 与 ProRes 422 预设 | 源分辨率 | 1920×1080       | 1080×1920       |

后期素材预设，分辨率都跟随源视频：

- **保留 Alpha · ProRes 4444**：ProRes 4444（4:4:4，带 Alpha，量化 12），MOV，PCM 音频。After Effects、Premiere 可以直接读到透明通道，最省事。只能 CPU 编码，但速度快于实时。
- **分离 Alpha · H.264 MP4**：彩色视频用 H.264 NVENC（p4、CQ 19，比上传预设的 CQ 29 画质更高，用于后期）、AAC 320 kbps，MP4，另外输出一个 `_alpha.mp4` 黑白遮罩（无损 H.264，实测比有损压缩还小）。在 AE 里把遮罩放在彩色视频上方，彩色层的轨道遮罩选“亮度遮罩”。文件最小。
- **ProRes 422 HQ · 剪辑素材**：ProRes 422 HQ（10-bit 4:2:2，不带 Alpha，量化 12），MOV，PCM 音频。不需要透明时的后期素材，各种剪辑软件都能流畅读取，比 4444 小。

ProRes 的“画质 · 量化”可以在“画质”页调整：1–64，数值越小质量越高、文件越大；0 为编码器默认（实测约为量化 12 的 4 倍大小）。各档量化的大小与画质实测见 [docs/编码器实测对比.md](docs/编码器实测对比.md) 第 7 节。

想自己设定长边，可以在“画质”页把输出分辨率选为“按长边缩放 · 自动识别横竖屏”。

> 各网站没有公开完整的上传规格（YouTube 除外），这些参数来自社区经验和本机实测，尚未经过全面的实际上传验证。参数依据和取舍见 [docs/平台上传预设.md](docs/平台上传预设.md)，硬件 / 软件编码的速度与画质实测见 [docs/编码器实测对比.md](docs/编码器实测对比.md)。

## RTX 视频增强（VSR）怎么选

VSR 在“RTX 增强”页设置，只能配合 NVEncC 使用，开始前要先点“验证本机 RTX 设置”。“NVIDIA QualityLevel”每 4 档为一组，组内从低到高是 Low / Medium / High / Ultra，数字越大效果越好，也越占显卡：

| 档位    | 作用                   | 适合的素材                           |
| ------- | ---------------------- | ------------------------------------ |
| 0       | 双三次放大（对照基线） | 只用来对比效果                       |
| **1–4** | VSR 放大，4 最好       | **干净的渲染画面放大，MMD 属于这类** |
| 8–11    | 去噪，保持原尺寸       | 有噪点的实拍、低光素材               |
| 12–15   | 去模糊，保持原尺寸     | 被压缩糊掉的素材                     |
| 16–19   | 补细节，保持原尺寸     | 原尺寸输出，只想让画面更锐           |
| 21 / 23 | 修复直播流压缩伪影     | 低码率直播录像                       |

MMD 渲染输出本身很干净，建议：

- **放大（如 1080p → 4K 上传）**：选 **4**，倍率 2。强度先用 1；如果线条边缘出现白边或过锐，降到 0.5–0.7。
- **不放大**：可以试 16–19，但要先和原片对比，看描边是否过锐。
- **去噪、去模糊、直播档**：MMD 一般用不上，去模糊还可能让描边过锐。

VSR 与普通的自定义分辨率不能同时使用。用默认 4K / 1080p 预设时，如果想改用 VSR 放大，请把输出分辨率改回“源分辨率”，再把 VSR 倍率设为 2。

## 从源码构建

需要 Node.js 22+、pnpm 和 Windows x64。

```powershell
pnpm install
pnpm build      # 类型检查并构建界面
pnpm start      # 启动开发版
mmd-plugin\build.cmd   # 编译 MMD 导出插件（需要 VS 2022 C++ 生成工具）
pnpm package    # 打包便携版
node scripts/zip-portable.mjs
```

开发版从本机安装目录读取编码工具。可以用环境变量 `MMD_ENCODER_TOOLS_ROOT` 指向其他工具目录。

### 测试

```powershell
$env:MMD_TEST_TOOLS_ROOT = "<工具目录>"
node --test tests/*.test.cjs   # 单元测试和真实引擎测试
node tests/desktop.mjs         # 桌面流程测试
node tests/desktop-tools.mjs   # 工具安装流程测试
node tests/desktop-recovery.mjs  # 出错恢复、预设与设置重启测试（MMD_PACKAGE_EXE 指向打包版时测打包版）
node tests/rtx-live.cjs        # RTX 实机测试（需要 NVIDIA 显卡）
```
